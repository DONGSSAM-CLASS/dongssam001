# writing-playbook.md — 글쓰기 공식 (구글 검색 + 애드센스형)

> post-writer 가 매 글 이 파일을 따른다. 네이버식(한 문장=한 줄, 사진 10장+, 키워드 5~7회 고정)과 다르다 — 구글은 **검색 의도 충족·정보 이득·신뢰**를 본다.
> 사용자의 교정 피드백은 `data/blog-profile.md` "교정 피드백"에 쌓고, 규칙이 되면 여기로 옮긴다.

## 1. 쓰기 전에 (설계 5줄 — front matter 에 기록)
1. **검색 의도**(searchIntent): 방법(how-to) / 비교 / 개념 설명 / 목록·체크리스트 / 계산 / 최신 소식 중 무엇?
2. **페르소나**: 이 키워드를 치는 1명 — 나이·상황·감정·이미 아는 것.
3. **정보 이득**(infoGain): 상위 글에 없는 것 1개 이상 — 아래 7장 목록에서 고른다. 못 고르면 주제를 바꾼다.
4. **형식**(format): 의도에 맞는 뼈대 (2장). 하루 안에서 같은 형식 2개 이하.
5. **도입 패턴**: 결론형 / 상황 공감형 / 손실 회피형 / 오해 바로잡기형 / 숫자형 — 같은 날 겹치지 않게.

## 2. 형식별 뼈대 (소제목 3~7개)
- **guide(방법)**: 결론 → 요약 상자 → 준비물·조건 → 단계별(캡처) → 막히는 곳·실수 → FAQ → 정리
- **comparison(비교)**: 결론(누구에게 무엇) → 비교 기준 → **비교표** → 항목별 장단점 → 상황별 추천 → FAQ
- **checklist(점검)**: 왜 지금 → 체크리스트(✔) → 항목별 설명 → 놓치기 쉬운 것 → 일정
- **faq(질문 모음)**: 핵심 답 요약 → 질문 6~10개를 묶음별 소제목으로 → 공식 문의처
- **case-study(사례)**: 상황 → 한 일(경험 은행 항목) → 결과(숫자는 사실만) → 배운 점 → 따라 하는 법
- **review(후기)**: 한 줄 평 → 쓰게 된 이유 → 좋았던 점/아쉬운 점(솔직) → 이런 분께 추천/비추천 → 대안
- **explainer(개념)**: 한 문장 정의 → 왜 중요한가 → 예시 → 헷갈리는 개념 비교 → 실제 적용
- **calculator(계산)**: 결론(공식) → 계산 방법 → **예시 계산 2~3개(가상이면 "예시" 명시)** → 계산 실수 → 공식 계산기 안내
- **news(소식 해설)**: 무엇이 바뀌었나(기준일) → 누구에게 영향 → 전후 비교표 → 할 일 → 공식 원문

## 3. 제목 (20~40자)
- 메인 키워드를 **앞쪽**에, 뒤에 이 글만의 약속(범위·방법 수·대상) — 예: "근로장려금 기한 후 신청, 지금 해도 받는 조건과 감액 기준"
- 시기성 있으면 연도. 과장·낚시 금지(충격·무조건·100%·역대급). 특수문자 장식 금지. 물음표·쉼표는 OK.
- 제목이 약속한 것을 첫 문단에서 바로 준다.

## 4. 첫 화면 (스크롤 없이 보이는 부분) — 이탈을 막는 곳
- 첫 문단 2~3문장: **질문에 대한 답(결론)** + 메인 키워드. 인사말·"오늘은 ~에 대해 알아볼게요" 금지.
- 둘째 문단: 이 글을 믿을 이유 한 줄 (화자 경험·기준일·공식 자료 기반) — `data/blog-profile.md` 사실만.
- 그다음 `:::summary` 핵심 요약 3~5줄. 목차는 빌드가 자동 삽입.

## 5. 본문 문장
- 말투: `data/blog-profile.md` 기준 (기본 해요체). 1인칭 경험은 experience-bank 에 있는 것만.
- 모바일 기준: 한 줄 한 문장 권장, 한 문단 2~4줄, 긴 설명은 목록·표·상자로.
- 숫자는 구체적으로(단위까지), 단 YMYL 숫자는 전부 `facts` 에 등록.
- 단정할 곳은 단정. "~할 수 있습니다"를 남발하지 않는다.
- **AI 티 제거** — 금지: "알아보겠습니다/살펴볼까요", "이번 포스팅에서는", "결론적으로/요약하자면/종합적으로", "다양한", "효과적인", "중요합니다" 남발, "도움이 되셨길 바랍니다", 같은 문장 구조 3번 연속, 모든 소제목 아래 똑같은 길이의 문단. 대신: 구체적 상황 묘사, 실제 화면 이름·메뉴 경로, 흔한 실수의 구체적 예.

## 6. 키워드 (자연스럽게)
- 메인: 제목 앞쪽 · 첫 문단 · 소제목 1~2개 · 마지막 문단. 본문 3~8회, 밀도 2% 이하 (게이트가 계산).
- 서브 2~3개: 소제목이나 FAQ 질문으로. 동의어·관련 개체(기관명·메뉴명·제도명)를 섞으면 주제 이해도가 올라간다.
- FAQ 질문은 실제 검색 질문 — WebSearch 로 "관련 검색어/함께 찾은 질문" 류를 참고하되 문장은 새로 쓴다.

## 7. 정보 이득 목록 (글마다 1개 이상 — infoGain 에 적는다)
1. **직접 경험**: experience-bank 항목 (신청해 본 과정, 막힌 곳, 걸린 시간, 결과)
2. **직접 만든 비교표**: 여러 공식 자료를 한 표로 (기준 명시)
3. **직접 계산**: 공식대로 계산한 예시 2~3개 (가상 수치면 "예시" 표기)
4. **원본 캡처**: 실제 화면·메뉴 경로 (개인정보 가림)
5. **공식 원문 해석**: 공고문의 어려운 조항을 쉬운 말로 + 원문 링크
6. **흔한 실수·함정**: 커뮤니티 질문에서 반복되는 실수(문장 복사 금지, 현상만)와 해결
7. **최신성**: 올해 바뀐 점 전후 비교 (기준일)

## 8. 사진·이미지
- 대표 이미지는 빌드가 자동 생성(제목 카드) — 본문엔 직접 찍거나 캡처하거나 만든 이미지 1장 이상 권장.
- 대체텍스트: 무엇이 보이는지 구체적으로 ("홈택스 장려금 신청 메뉴 위치 — 상단 '장려금·연말정산·전자기부금' 탭").
- 용량: 한 장 500KB 이하 권장 (페이지 속도 → 체류·광고 노출).
- 인터넷 이미지·타 블로그 캡처 금지.

## 9. 링크
- 외부: 공식 출처 위주 1~5개 (빌드가 "참고한 공식 자료" 섹션 자동 생성).
- 내부: 같은 클러스터 글 1~3개 `[[slug|앵커]]` — 문맥 안에서 자연스럽게 ("신청 전 소득 기준이 헷갈리면 [[...|소득 기준 정리 글]]부터").

## 10. 마무리
- 메인 키워드가 들어간 한두 줄 정리 + 다음 행동(공식 사이트에서 무엇을 누르면 되는지).
- 댓글 질문 유도는 OK. **광고 클릭 유도 절대 금지.**
