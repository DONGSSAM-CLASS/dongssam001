# 역사탐정 프로젝트

중·고등학생 역사 정보 검증 및 출처 기재 실습 웹앱.
2022 개정 교육과정 중학교 「역사」 수업(3~4차시)에서 학생 1인 1기기로 쓰도록 만들었습니다.

> **이 앱이 가르치려는 것**
> 역사적 사실을 외우는 것이 아니라, **무엇을 근거로 믿을지 스스로 정하는 기준**을 갖는 것.

## ⚠️ 먼저 읽어 주세요

### 1. 앱 속 'AI 답변'은 실제 AI의 답이 아닙니다

1단계의 답변은 실시간 생성 결과가 아니라 **교사가 검수할 수 있도록 미리 작성한 JSON 스크립트**입니다. 타이핑 효과는 화면 연출이며, 몇 번을 눌러도 같은 답변이 나옵니다. 이렇게 한 이유는:

- 수업 중 매번 다른 답변이 나오면 교사가 정답·오류를 통제할 수 없습니다.
- 학생이 검증할 **오류를 의도적으로 심어 두어야** 훈련이 성립합니다.
- API 키·비용·교내망 차단 문제가 없고, 언제나 동일하게 동작합니다.

### 2. 일부 자료는 실재하지 않는 수업용 가상 예시입니다

각 케이스의 `src-05`는 '신뢰도 낮은 자료 알아보기' 훈련용 대조 자료로, **실재하는 게시글이 아니라** 인터넷에서 흔히 보이는 서술 방식을 재구성한 것입니다. 실재하지 않는 글에 실재하는 주소를 붙이지 않기 위해 **URL을 두지 않았고**(`url: null`, `synthetic: true`), 화면에는 붉은 배지로 표시됩니다. 수업에서 반드시 안내해 주세요.

### 3. 사료 링크는 아직 자동 확인되지 않았습니다 — 수업 전 한 번 돌려 주세요

```bash
npm run verify-links
```

모든 사료 URL은 화이트리스트 도메인에서만 가져왔고, 주소가 실재하는지 검색으로 대조해 넣었습니다. 다만 **개발 환경의 네트워크 정책이 모든 아카이브 도메인을 차단**해 자동 점검을 완료하지 못했으므로, 현재 전건 `urlVerified: false`입니다. 이는 "링크가 죽었다"가 아니라 **"아직 확인하지 못했다"**는 뜻이며, 화면에도 '링크 미확인'으로 정직하게 표시됩니다.

외부 접속이 되는 환경에서 위 명령을 돌린 뒤 `-- --write`로 반영해 주세요. 스크립트는 **차단(403)과 죽은 링크(404)를 구분해** 보고하므로, 교내망에서 돌려 전부 '차단됨'이 나오더라도 당황하지 않으셔도 됩니다.

## 수업 운영 예시 (3~4차시)

### 1차시 — 왜 검증해야 하는가 (45분)

| 시간 | 활동 |
|---|---|
| 5분 | 도입: "AI가 알려 준 역사, 어디까지 믿을 수 있을까?" 교사가 AI 답변 한 편을 띄우고 학생 반응 듣기 |
| 10분 | 앱 접속, 트랙·케이스 선택. **0단계** 탐구 질문 다듬기 |
| 15분 | **1~2단계** AI 답변 읽고 문장별 판정. 판정 후 짝과 비교 |
| 10분 | 전체 공유: 판정이 갈린 문장을 중심으로. "왜 그렇게 판정했나?"만 묻고 정답은 말하지 않기 |
| 5분 | 정리: 오류 유형 범례(홈 화면 하단) 훑기 |

**추천 케이스**: 마리 앙투아네트(연대 대조만으로 결론이 나서 성공 경험을 주기 좋음)

### 2차시 — 사료를 직접 읽는다 (45분)

| 시간 | 활동 |
|---|---|
| 5분 | 복습: 지난 시간 판정이 갈렸던 문장 |
| 10분 | 교사 시범: 사료 1건을 함께 열어 **출처 확인 → 맥락화 → 교차검증** 3단계 시연 |
| 25분 | **3단계** 워크벤치 개별 활동. 오답 시 힌트 먼저, 2회 오답 후 해설 공개 |
| 5분 | 정리: "자료가 말해 주지 않는 것"을 한 가지씩 발표 |

**유의**: 워크벤치는 이 앱에서 가장 시간이 오래 걸립니다. 한 차시를 온전히 쓰는 것을 권합니다.

### 3차시 — 출처를 밝히고 내 글을 쓴다 (45분)

| 시간 | 활동 |
|---|---|
| 10분 | **4단계** APA 출처 기재. 3회 시도 후 정답 공개, '다시 입력해 보기'로 재연습 |
| 5분 | 왜 출처를 밝히는가: "남이 같은 자료를 찾아갈 수 있게 하기 위해" |
| 20분 | **5단계** 세 줄 메모 + 나의 서사 작성 |
| 10분 | **6단계** 루브릭 자기평가, 리포트 인쇄 또는 PNG 저장 |

### 4차시(선택) — 논쟁을 경험한다 (45분)

논쟁적 케이스(발해 / 독도 / 신묘년조 / 실학 / 마그나 카르타 / 간디)를 골라, 학생을 해석별 모둠으로 나눕니다.

- 각 모둠은 **자기 해석이 어떤 자료의 어느 대목에 근거하는지** 정리합니다.
- 토론의 규칙: **상대 해석을 반박할 때도 반드시 자료를 들 것.**
- 마무리 질문: "오늘 우리가 확인한 것은 무엇이고, 아직 확인하지 못한 것은 무엇인가?"

> **어느 한 해석을 정답으로 제시하지 마세요.** 이 앱의 논쟁적 케이스는 복수 해석을 각각의 근거와 함께 병기하도록 설계되어 있습니다. 교사 모드의 '복수 해석' 항목을 참고하세요.

### 운영 팁

- **교사 모드 암호는 배포 전에 바꾸세요.** `src/pages/TeacherPage.jsx`의 `GATE_WORD`. 코드에 그대로 들어 있으므로 보안 장치가 아니라 오조작 방지용 가림막입니다.
- **활동지 인쇄**: 교사 모드 → 학급용 활동지 → 케이스 선택 → 인쇄. 기기가 모자라는 교실에서 종이 병행에 쓸 수 있습니다.
- **기기를 옮길 때**: 홈 화면에서 '이어받기 코드'를 만들어 복사합니다. 함께 나오는 6자리 확인 번호는 코드를 제대로 옮겼는지 대조하는 체크섬이며, 그 6자리만으로는 복원되지 않습니다(백엔드가 없기 때문입니다).
- **글자 크기**: 화면 오른쪽 위 작게/보통/크게 버튼. 기기별로 저장됩니다.

## 기술 구성

- **React 18 + Vite 5 + JavaScript(JSX)**, 스타일은 **Tailwind CSS 3**
- 상태 관리는 React 내장 훅만 사용 (외부 상태 라이브러리 없음)
- **백엔드 없음.** 모든 학습 데이터는 `src/data/*.json`에 정적으로 포함
- 라우팅은 `react-router-dom` v6 **HashRouter** — 정적 호스팅에서 새로고침 404가 나지 않도록
- 한글 폰트는 `@fontsource/noto-sans-kr` **로컬 번들**(CDN 의존 없음). 분할 서브셋 400/700만 사용해, 실제로 쓰인 글자에 해당하는 조각만 내려받습니다
- 외부 API 호출 없음, 접속 기록 수집 코드 없음
- 애니메이션은 CSS transition 수준으로 제한, `prefers-reduced-motion` 대응

### 접근성 · 저사양 대응

- 본문 16px 이상 강제, 줄간격 1.7, 글자 크기 3단계 조절
- 모바일 우선. 워크벤치는 좁은 화면에서 탭 전환으로 바뀝니다
- 종이질감 배경은 이미지 없이 CSS 그라디언트로만 구현
- 학생이 처음 만나는 화면에 필요 없는 코드(교사 모드·가이드·출처 고지)는 별도 청크로 분리

## 케이스 추가·수정하기

`src/data/cases.korea.json` 또는 `cases.world.json`에 항목을 추가합니다. 스키마는 기존 케이스를 그대로 따르면 되고, 고친 뒤에는 반드시 점검을 돌려 주세요.

```bash
npm run check          # 스키마·정답·채점 규칙 일관성
npm run verify-links   # 새로 넣은 URL 확인
```

`npm run check`가 잡아 주는 것(29건):

- 케이스 id 중복, 비문자 자료 누락
- `checkWith` / `apaTarget.sourceId`가 실재하는 사료를 가리키는지
- **APA 정답을 그대로 입력하면 정말 100점이 나오는지**
- 워크벤치 3단계 × (객관식 2 + 단답 1) 구성, `answerIndex` 범위
- 모든 문항의 힌트·해설 존재 여부
- **단답형 채점 키워드가 2글자 이상인지** (1글자 키워드는 채점기가 영영 맞출 수 없습니다)
- 오류를 심은 문장에 `errorType`이 있는지, 정상 문장에는 없는지
- 논쟁적 주제(`contested: true`)에 해석이 둘 이상 병기되었는지
- URL 없는 사료가 `synthetic: true`로 표시되었는지

### 사료를 넣을 때 지켜야 할 것

1. **화이트리스트 도메인에서만** 가져옵니다 (`scripts/verify-links.mjs`의 `WHITELIST`).
2. **실재를 확인하지 못한 URL은 넣지 않습니다.** 확인하지 못했으면 `urlVerified: false`로 두고 보고합니다.
3. 개인 블로그·위키 형식 사이트·커뮤니티·언론사 칼럼은 1차 근거로 쓰지 않습니다. 대조 자료로 쓸 때는 `reliability: "low"`로 명시합니다.
4. 실재하지 않는 예시 자료는 `synthetic: true`, `url: null`로 둡니다.
5. 인용은 원문을 확인한 경우에만 `excerptKind: "quote"`, 그렇지 않으면 `"summary"`로 적습니다.
6. 논쟁적 주제는 `contested: true`와 `interpretations`(복수 해석)를 함께 넣습니다.

## 알려진 한계

- **사료 링크가 자동 확인되지 않았습니다.** 위 '먼저 읽어 주세요' 3번 참고.
- **6자리 복구 코드만으로는 진행 상황을 복원할 수 없습니다.** 백엔드가 없어 6자리에 데이터를 담을 수 없기 때문입니다. 실제 데이터는 긴 Base64 '이어받기 코드'에 들어 있고, 6자리는 옮겨 적기를 대조하는 확인 번호로 쓰입니다. 화면에도 그렇게 안내합니다.
- **PNG 저장은 기기에 따라 실패할 수 있습니다.** 외부 라이브러리 없이 SVG `foreignObject` → canvas 경로를 쓰기 때문입니다. 실패 시 안내가 뜨며, 인쇄(PDF 저장)로 대체할 수 있습니다.
- **폰트 CSS가 큽니다**(gzip 약 58KB). 분할 서브셋을 쓰면 실제 폰트 파일은 필요한 조각만 내려받지만, `@font-face` 선언 자체가 많아집니다. 통합 서브셋은 굵기당 850KB 한 덩어리라 더 불리해 현재 방식을 택했습니다.
- **교사 모드 암호는 보안 장치가 아닙니다.** 코드에 그대로 들어 있습니다.
