> 아래 `---` 사이를 통째로 복사해 Codex에 붙여넣으세요.

## 프로젝트 개요

`history-factcheck-lab/` 은 **「역사탐정 프로젝트」** — 2022 개정 교육과정 중학교 「역사」 3~4차시 수업에서 학생 1인 1기기로 쓰는 웹앱입니다. 학생이 AI 답변의 오류를 찾아내고, 사료를 직접 검증하고, APA 7판으로 출처를 기재하는 훈련을 합니다.

**Phase 1~7이 모두 완료된 상태입니다.** 케이스 12건, AI 문장 72개(오류 24개 포함), 사료 60건, 검증 문항 108개가 들어 있고, 자체 점검 29건과 헤드리스 브라우저 전수 테스트를 통과했습니다.

**반드시 `history-factcheck-lab/CODEX_HANDOFF.md` 를 먼저 끝까지 읽고 제약 조건을 숙지한 뒤 작업하세요.**

### 이 앱이 가르치려는 것

역사적 사실을 외우는 것이 아니라, **무엇을 근거로 믿을지 스스로 정하는 기준**을 갖는 것입니다. 이 목표를 해치는 변경(정답을 바로 보여 주기, 논쟁을 하나의 정답으로 정리하기 등)은 하지 마세요.

### 핵심 제약

- React 18 + Vite 5 + JavaScript(JSX) + Tailwind CSS 3
- 상태 관리는 **React 내장 훅만** (외부 상태 라이브러리 금지)
- **백엔드 없음.** 학습 데이터는 전부 `src/data/*.json` 정적 포함
- **외부 API 호출 없음**, CDN 의존 없음, 폰트는 로컬 번들
- 라우팅은 HashRouter
- `localStorage` 외 학생 개인정보 수집 금지
- 모든 UI 텍스트는 한국어
- 학교 크롬북 기준: 번들 최소화, 애니메이션은 CSS transition 수준까지

### 절대 하면 안 되는 것

1. **앱 속 'AI 답변'을 실시간 LLM 호출로 바꾸지 말 것.** 미리 작성된 JSON 스크립트를 재생하는 시뮬레이터이며, 교사가 오류를 통제할 수 있어야 훈련이 성립합니다.
2. **실재를 확인하지 못한 URL을 넣지 말 것.** 확인 못 했으면 `urlVerified: false`로 두고 보고하세요.
3. **각 케이스의 `src-05`(수업용 가상 예시)에 URL을 채워 넣지 말 것.** 실재하지 않는 글이므로 `url: null`, `synthetic: true` 입니다.
4. **논쟁적 주제에서 한 가지 해석만 정답으로 제시하지 말 것.**
5. **워크벤치 오답 시 정답을 바로 알려 주지 말 것.** 1회 오답 → 힌트만, 2회 오답 후 해설 공개.

## 시작하기

```bash
cd history-factcheck-lab
npm install

# 교사 모드 암호 설정 (필수 — 안 하면 배포가 거부됩니다)
cp .env.example .env.local
# .env.local 에서 VITE_TEACHER_PASSCODE 값을 원하는 암호로 수정

npm run check      # 자체 점검 29건 — 먼저 통과하는지 확인
npm run dev        # http://localhost:5173
```

**케이스 데이터를 고친 뒤에는 반드시 `npm run check` 를 실행하세요.**

## 앞으로 진행할 작업 (우선순위 순)

### 1. 사료 링크 검증 — 최우선

현재 사료 URL 48건이 전부 `urlVerified: false` 입니다. 이는 링크가 죽었다는 뜻이 아니라, **이전 작업 환경의 네트워크 정책이 모든 아카이브 도메인을 차단(HTTP 403)해 확인을 완료하지 못했다**는 뜻입니다.

```bash
npm run verify-links              # 점검만
npm run verify-links -- --write   # 결과를 urlVerified에 반영
```

- 스크립트는 **차단(403)과 죽은 링크(404)를 구분**합니다. 전부 '차단됨'이면 네트워크 문제이지 링크 문제가 아닙니다.
- 실패한 링크는 **화이트리스트 도메인 안에서** 대체 링크를 찾으세요 (`scripts/verify-links.mjs`의 `WHITELIST`).
- 대체 링크를 못 찾으면 임의로 만들어 넣지 말고 목록으로 보고하세요.

### 2. Firebase Hosting 배포

`firebase login` 이 브라우저 OAuth를 요구해 이전 환경에서는 수행하지 못했습니다.

```bash
# 처음 한 번만
npx firebase login        # 브라우저가 열립니다
npx firebase use --add    # .firebaserc 가 자동으로 채워집니다

# 배포
npm run deploy
```

`npm run deploy` 는 배포 전 6가지를 점검하고(암호 설정·프로젝트 ID·로그인·자체점검·빌드·암호 반영 여부) 문제가 있으면 무엇을 고칠지 안내하고 멈춥니다.

배포 뒤 확인: ① `/#/teacher` 새 암호 ② 모바일 워크벤치 탭 ③ `npm run verify-links`

### 3. 역사 내용 검수 — 가장 가치 있는 작업

이 프로젝트에서 가장 심각한 오류는 코드 버그가 아니라 **잘못된 역사 정보**입니다.

교사 모드(`/#/teacher`) → '정답·해설 일괄 보기'에서 12개 케이스를 통독하며 다음을 확인하세요.

- 연도·인명·수치가 정확한가
- 인용문이 원문과 일치하는가 (`excerptKind: "quote"`인 항목)
- 논쟁적 주제에서 복수 해석이 공정하게 병기되었는가
- 특정 국가·민족·종교에 대한 비하나 단정적 가치 평가가 없는가
- 심어 둔 오류(`errorType`)의 해설이 정확한가

의심스러운 항목은 고치지 말고 먼저 목록으로 보고하세요.

### 4. 접근성(a11y) 점검

- 키보드만으로 6단계 전체 흐름 탐색 가능한지
- 스크린 리더 호환성 (`aria-label`, `aria-live`, `role`)
- 색상 대비 WCAG AA 충족 여부 (`tailwind.config.js`의 `ink` / `kraft` / `alert`)
- 글자 크기 3단계 조절이 모든 화면에서 깨지지 않는지

### 5. 실제 수업 적용 후 피드백 반영

- 워크벤치 문항 난이도 조정 (현재 케이스당 9문항이 가장 시간이 오래 걸림)
- `estimatedMinutes` 실측값으로 갱신
- 학생이 자주 막히는 지점의 힌트 문구 개선

### 6. 케이스 추가

스키마는 기존 케이스를 그대로 따르세요. 추가 시 지켜야 할 것:

1. 사료는 화이트리스트 도메인에서만, 실재 확인된 URL만
2. 비문자 자료(`nonText: true`) 최소 1건 포함
3. 대조용 저품질 자료는 `synthetic: true`, `url: null`, `reliability: "low"`
4. AI 문장 6개 중 2개에 오류를 심고 `errorType` 지정
5. 워크벤치 3단계 × (객관식 2 + 단답 1), 전부 힌트·해설 포함
6. 단답형 `acceptKeywords`는 **2글자 이상** (1글자는 채점기가 영영 못 맞춤)
7. 논쟁적이면 `contested: true` + `interpretations` 2개 이상
8. `npm run check` 통과 확인

## 과거에 실제로 발견해 고친 버그 (재발 방지)

같은 실수를 반복하지 않도록 기록해 둡니다.

1. **PNG 저장이 동작하지 않음** — `foreignObject`가 든 SVG를 `blob:` URL로 캔버스에 그리면 캔버스가 오염되어 `toDataURL`이 막힙니다. **`data:` URI를 써야** 합니다.
2. **다운로드 파일명이 `download`로 저장됨** — 파일명에 한글을 쓰면 크로뮴이 `download` 속성을 무시합니다. **영문 파일명**을 쓰세요.
3. **빠른 연속 클릭 시 상태 유실** — 단계 컴포넌트가 prop 스냅샷에 병합하던 문제. **반드시 함수형 업데이트**(`onChange((prev) => ...)`)를 쓰세요.
4. **1글자 채점 키워드는 영영 정답 처리 안 됨** — 채점기가 1글자 답안을 무효 처리하기 때문. `npm run check`가 막습니다.
