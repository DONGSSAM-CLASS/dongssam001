## 2. 기술 스택과 제약

- **React 18 + Vite 5 + JavaScript(JSX)**, **Tailwind CSS 3**
- 상태 관리는 **React 내장 훅만** (zustand 등 외부 상태 라이브러리 금지)
- **백엔드 없음.** 학습 데이터는 전부 `src/data/*.json` 정적 포함

- 폰트는 `@fontsource/noto-sans-kr` **로컬 번들** (CDN 의존 금지)
- **외부 API 호출 없음**, 접속 기록 수집 코드 없음
- 애니메이션은 CSS transition 수준까지만, `prefers-reduced-motion` 대응

### 접근성·저사양 대응 (학교 크롬북 기준)

- 본문 16px 이상 강제, 줄간격 1.7, 글자 크기 3단계 조절
- 모바일 우선. 워크벤치는 좁은 화면에서 탭 전환
- 종이질감 배경은 이미지 없이 CSS 그라디언트로만
- 학생이 처음 만나지 않는 화면(교사 모드·가이드·출처 고지)은 별도 청크

## 4. ⚠️ 반드시 알아야 할 3가지

### (1) 앱 속 'AI 답변'은 실제 AI의 답이 아니다

1단계의 답변은 **미리 작성된 JSON 스크립트를 재생하는 시뮬레이터**다. 타이핑 효과는 연출일 뿐이고 몇 번을 눌러도 같은 답변이 나온다.

**절대로 실시간 LLM 호출로 바꾸지 말 것.** 이유:
- 수업 중 매번 다른 답변이 나오면 교사가 정답·오류를 통제할 수 없다
- 학생이 검증할 **오류를 의도적으로 심어 두어야** 훈련이 성립한다
- API 키·비용·교내망 차단 문제가 없고 언제나 동일하게 동작한다

### (2) 각 케이스의 `src-05`는 실재하지 않는 가상 예시다

'신뢰도 낮은 자료 알아보기' 훈련용 대조 자료로, 인터넷에서 흔히 보이는 서술 방식을 재구성한 것이다. **실재하지 않는 글에 실재하는 주소를 붙이지 않기 위해 URL을 두지 않았다**(`url: null`, `synthetic: true`). 화면에는 붉은 배지가 뜬다.

이 자료들에 URL을 채워 넣지 말 것. `npm run check`가 막는다.

### (3) 사료 링크가 아직 자동 확인되지 않았다 — 최우선 과제

모든 URL은 화이트리스트 도메인에서만 가져왔고 실재를 검색으로 대조해 넣었지만, **작업 환경의 네트워크 정책이 모든 아카이브 도메인을 차단(HTTP 403)해 자동 점검을 완료하지 못했다.** 그래서 48건 전부 `urlVerified: false`다.

이는 "링크가 죽었다"가 아니라 **"아직 확인하지 못했다"**는 뜻이며, 화면에도 '링크 미확인'으로 표시된다.

```bash
npm run verify-links              # 점검만
npm run verify-links -- --write   # 결과를 urlVerified에 반영
```

스크립트는 **차단(403)과 죽은 링크(404)를 구분**한다. 전부 '차단됨'으로 나오면 네트워크 문제이지 링크 문제가 아니다.

## 5. 학습 루프 6단계

| 단계 | 화면 | 학생 활동 | 교육과정 근거 |
|---|---|---|---|
| 0 | 탐구 질문 다듬기 | 4개 중 개연성 있는 질문 고르기 → 자기 질문 | 교수·학습 (2)-(나), 평가 (2)-(라)① |
| 1 | AI에게 묻기 | 사전 작성된 답변 수신 (문장마다 번호) | 교수·학습 (2)-(마) |
| 2 | 문장 판정 | 사실 / 의심스러움 / 확인 불가 | 과정·기능 ② |
| 3 | 사료 검증 워크벤치 | 출처 확인 → 맥락화 → 교차검증 | 교수·학습 (2)-(가), 과정·기능 ① |
| 4 | 출처 기재 | APA 7판 직접 입력 → 자동 채점 | 과정·기능 ③ |
| 5 | 세 줄 메모 + 서사 | 메모 3줄 → 3~5문장 역사 서사 | 과정·기능 ④, 평가 (2)-(나) |
| 6 | 탐정 리포트 | 루브릭 4축 자기평가 + 인쇄/PNG | 평가 (2)-(다) |

### 워크벤치 오답 처리 (건드리지 말 것)

1회 오답 → **힌트만** (자료의 어느 부분을 보라) → 2회 오답 후 **해설 공개**

정답을 바로 알려 주면 이 앱의 교육 목표가 무너진다.

### APA 채점 (100점 만점)

항목당 20점 × 5개(저자/연도/제목/사이트/URL), 구두점 오류는 항목당 5점 감점.
"틀렸습니다"가 아니라 **"연도 자리에 괄호가 빠졌어요. APA에서는 (2024)처럼 씁니다."** 식으로 돌려준다.
3회 시도 후 정답 공개, '다시 입력해 보기'로 재연습.

## 6. 반드시 지켜야 할 규칙

### 역사 콘텐츠

1. **실재를 확인하지 못한 URL은 절대 넣지 않는다.** 확인 못 했으면 `urlVerified: false`로 두고 보고한다.
2. 사료는 **화이트리스트 도메인에서만** 가져온다 (`scripts/verify-links.mjs`의 `WHITELIST`).
3. 확인되지 않은 연도·인명·수치를 서술에 넣지 않는다.
4. **논쟁적 주제에서 한 가지 해석만 정답으로 제시하지 않는다.** `contested: true`면 `interpretations`를 2개 이상 병기하고, 학생에게는 "어느 해석이 어떤 자료에 기대고 있는지"를 묻는다.
5. 특정 국가·민족·종교에 대한 비하나 단정적 가치 평가 금지.
6. 인용은 원문을 확인한 경우에만 `excerptKind: "quote"`, 아니면 `"summary"`.
7. 개인 블로그·위키 형식 사이트·커뮤니티·언론사 칼럼은 1차 근거 금지. 대조 자료로만 `reliability: "low"`.

### 코드

8. `localStorage` 외 학생 개인정보 수집 금지. 이름 입력은 선택, 기기 밖 전송 없음.
9. 단계 상태 갱신은 **반드시 함수형 업데이트**로. (`onChange((prev) => ...)`)
   과거에 prop 스냅샷에 병합해서 빠른 연속 클릭 시 상태가 유실되는 버그가 있었다.
10. 단답형 `acceptKeywords`는 **2글자 이상**. 채점기가 1글자 답안을 무효 처리하므로 1글자 키워드는 영영 맞출 수 없다. `npm run check`가 막는다.
11. 다운로드 파일명에 한글을 쓰지 않는다. 크로뮴이 `download` 속성을 무시해 확장자 없는 `download` 파일이 된다.
12. PNG 저장은 `foreignObject` SVG를 **`data:` URI로** 넘겨야 한다. `blob:` URL은 캔버스를 오염시켜 `toDataURL`이 막힌다.

## 8. 교사 모드 암호

`.env.local`의 `VITE_TEACHER_PASSCODE`에서 빌드 시점에 읽는다.
`.env.local`은 `.gitignore`(`*.local`)에 걸려 저장소에 올라가지 않는다.

**보안 장치가 아니다.** 백엔드가 없어 값이 빌드 결과물에 그대로 들어간다. 개발자 도구를 열 줄 아는 사람은 찾아낼 수 있다. 학생 기기에서 정답 화면이 실수로 열리는 것을 막는 가림막일 뿐이므로, 다른 곳에서 쓰는 비밀번호를 재사용하면 안 된다.

설정하지 않으면 기본값 `teacher`가 쓰이고, 교사 모드 화면에 경고가 뜨며, `npm run deploy`가 배포를 거부한다.

## 9. 배포 (Firebase Hosting) — 남은 작업

### 아직 안 된 이유

`firebase login`이 **브라우저 OAuth를 요구**해 작업 컨테이너에서 수행할 수 없었다. 계정 자격증명이 없어 `firebase login:list`가 `No authorized accounts`를 반환한다. 네트워크 자체는 Firebase API에 도달 가능하다(인증만 없음).

### 처음 한 번만

```bash
# 1) Firebase 콘솔에서 프로젝트 생성 (없다면)
#    https://console.firebase.google.com

# 2) 로그인 — 브라우저가 열린다
npx firebase login

# 3) 이 폴더를 프로젝트에 연결 (.firebaserc 가 자동으로 채워진다)
npx firebase use --add
```

### 배포

```bash
npm run deploy
```

이 한 줄이 순서대로 수행한다.

1. 교사 모드 암호 설정 여부 (기본값이면 중단)
2. Firebase 프로젝트 ID (플레이스홀더면 중단)
3. Firebase 로그인 여부 (안 되어 있으면 중단)
4. `npm run check` 29건
5. `npm run build`
6. **빌드 결과물에 설정한 암호가 실제로 반영되었는지 재확인**
7. `firebase deploy --only hosting`

점검에 걸리면 무엇을 어떻게 고치면 되는지 안내하고 멈춘다.

### 배포 뒤 확인할 것

1. `/#/teacher` 에서 새 암호로 들어가지는지
2. 학생 기기(모바일)에서 워크벤치 탭 전환이 정상인지
3. `npm run verify-links` 로 사료 링크가 살아 있는지

`firebase.json`에는 정적 자원 장기 캐시, `index.html` no-cache, 보안 헤더와 CSP가 설정되어 있다.

## 10. 알려진 제약

- **사료 링크 48건이 미확인 상태다.** 4절 (3) 참고. 최우선 과제.
- **6자리 복구 코드만으로는 복원할 수 없다.** 백엔드가 없어 6자리에 데이터를 담을 수 없다. 실제 데이터는 긴 Base64 '이어받기 코드'에 들어 있고, 6자리는 옮겨 적기를 대조하는 체크섬이다. 화면에도 그렇게 안내한다.
- **PNG 저장은 기기에 따라 실패할 수 있다.** 외부 라이브러리 없이 SVG `foreignObject` → canvas 경로를 쓴다. 실패 시 안내가 뜨고 인쇄(PDF)로 대체 가능.
- **폰트 CSS가 크다** (gzip 약 58KB). 분할 서브셋이라 실제 폰트 파일은 필요한 조각만 받지만 `@font-face` 선언이 많다. 통합 서브셋은 굵기당 850KB 한 덩어리라 더 불리해 현재 방식을 택했다.
- **교사 모드 암호는 보안 장치가 아니다.** 8절 참고.

## 11. 다음에 할 만한 일 (우선순위 순)

1. **사료 링크 검증** — `npm run verify-links -- --write`. 깨진 링크가 있으면 화이트리스트 안에서 대체 링크를 찾는다.
2. **Firebase 배포** — 9절.
3. **실제 수업 적용 후 피드백 반영** — 워크벤치 문항 난이도, 소요 시간 실측.
4. **접근성 점검** — 키보드만으로 6단계 전체 탐색, 스크린 리더, 색상 대비 WCAG AA.
5. **케이스 추가** — 스키마는 기존 케이스를 그대로 따르고, 6절 규칙과 `npm run check`를 지킬 것.
