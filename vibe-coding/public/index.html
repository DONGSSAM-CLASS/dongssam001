무료 도구 실습 · 약 60분부터

설치 없이, 첫 퀴즈에서 배포까지

Canva는 현재 계정에서 제공되는 Code 기능과 AI 사용량 안에서 실습합니다. 기능이 없으면 Gemini를 선택하세요. Gemini도 무료 사용 한도가 있으며, 학교 계정은 관리자 설정에 따라 메뉴와 공유 방식이 다를 수 있습니다.

Canva AI · 버튼을 눌러 만드는 첫 웹앱

01

준비물과 계정 확인하기

이 단계가 끝나면: 브라우저에서 실습할 계정을 정했습니다.

준비물은 인터넷이 연결된 PC, Chrome 또는 Edge, Canva 로그인 계정입니다. 프로그램 설치나 결제 정보 입력 없이 시작하세요.

  1. Canva 열기를 누르고 평소 쓰는 계정으로 로그인합니다.
  2. 학교에서 지원받은 교육용 계정이라면 해당 팀에 들어와 있는지 확인합니다.
  3. 홈에서 코드(Code) 또는 Canva AI → 코드를 찾습니다. 프레젠테이션 편집 화면의 일반 텍스트 입력칸과는 다릅니다.
무료 실습은 ‘추가 결제 없이 현재 계정에서 제공되는 범위’가 기준입니다. Canva Code는 요금제와 순차 제공 여부에 따라 접근과 사용량이 다릅니다. 메뉴가 없거나 업그레이드가 필요하면 결제하지 말고 Gemini 실습을 선택하세요.
02

명령어 입력창 찾기

이 단계가 끝나면: AI에게 만들 내용을 부탁할 준비가 됐습니다.

  1. 홈의 코드를 누릅니다. 화면에 따라 Canva AI에서 코드 만들기를 선택할 수도 있습니다.
  2. 만들고 싶은 것을 설명하는 입력칸이 보이는지 확인합니다.
  3. 처음에는 새 작업을 열고, 아래 예제 하나만 만들어 봅니다.
교사에게는 보이는데 학생에게는 코드 메뉴가 없어요

교육용 팀의 AI 이용 설정, 연령 및 계정 권한, 기능 제공 상태가 다를 수 있습니다. 새로고침 후 로그인 계정과 팀을 확인하고, 학교나 팀 관리자에게 코드 기능 허용 여부를 확인하세요. 원인을 단정하거나 유료 결제를 먼저 진행하지 마세요. 연수 실습은 교사 본인의 허용된 계정 또는 Gemini로 이어갑니다.

03

작게 기획하기

이 단계가 끝나면: 처음 만들 기능을 세 가지로 정했습니다.

처음부터 학급 전체 관리 시스템을 만들 필요는 없습니다. 5문항 퀴즈로 시작해 보세요.

  • 언제 쓰나요? 수업 마무리 5분

첫 작품은 학생별 성적 수집 없이 혼자 풀어 보는 형태로 만듭니다. 아래 프롬프트는 교과와 주제만 바꾸어 재사용할 수 있습니다.

04

첫 웹앱 만들기

이 단계가 끝나면: 눌러 볼 수 있는 퀴즈 화면이 생겼습니다.

아래 내용을 복사해 코드 입력창에 붙여넣고 생성을 누르세요. 완성된 화면을 클릭해 첫 문제를 풀어 봅니다.

복사해서 AI에게 보내세요
중학생이 수업 마무리에 풀 수 있는 「세계사 핵심 개념 퀴즈」 웹앱을 만들어 주세요.
객관식 5문항을 한 문제씩 보여 주고, 답을 고르면 정답 여부와 한 문장 해설을 표시해 주세요.
예시 문항은 산업 혁명의 시작 지역, 프랑스 혁명의 시작 연도, 제1차 세계 대전의 발발 연도, 르네상스의 시작 지역, 냉전의 두 중심 국가로 구성해 주세요. 사실관계를 확인할 수 있도록 문항과 정답 목록도 함께 적어 주세요.
마지막에는 5문제 중 맞힌 개수와 다시 풀기 버튼을 보여 주세요.
한국어로 표시하고 휴대폰에서도 버튼과 글자가 잘 보이게 해 주세요. 이름 입력, 로그인, 서버 저장, 외부 AI 호출은 넣지 마세요.

긴 설명을 읽기보다 먼저 한 번 실행해 보세요. 정답과 해설은 교사가 교과서나 수업 자료와 대조한 뒤 사용합니다.

05

직접 눌러 보고 말로 고치기

이 단계가 끝나면: 퀴즈를 끝까지 풀고 불편한 점 하나를 고쳤습니다.

  1. 일부러 오답을 골라 해설이 맞는지 확인합니다.
  2. 5문제를 모두 푼 뒤 점수가 맞는지 확인합니다.
  3. 다시 풀기를 누르면 첫 문제와 점수가 초기화되는지 확인합니다.
  4. 화면을 좁혀 글자와 버튼이 잘리는지 살펴봅니다.
복사해서 AI에게 보내세요
정답 확인 버튼을 눌러도 다음 문제로 넘어가지 않습니다.
답 선택 → 정답과 해설 표시 → 다음 문제 버튼 순서로 동작하게 고쳐 주세요.
마지막 문제에서는 결과 화면으로 이동하게 해 주세요. 문항 내용과 현재 색상은 유지해 주세요.

문제가 다르다면 첫 문장을 실제 증상으로 바꾸세요. 예: “휴대폰에서 다음 문제 버튼이 잘립니다. 버튼을 한 줄 아래로 옮겨 주세요.”

06

Canva에서 웹사이트로 게시하기

이 단계가 끝나면: 편집 화면 밖에서도 열리는 웹사이트 주소를 얻었습니다.

  1. 코드 창 오른쪽 위 게시(Publish) 또는 웹사이트 게시를 선택합니다.
  2. 사이트 주소와 제목을 확인합니다. 무료 Canva 주소를 선택하고, 유료 도메인 구매는 건너뜁니다.
  3. 설정을 확인한 뒤 게시를 누릅니다.
  4. 완료 화면의 라이브 주소를 복사합니다. 디자인 편집 링크를 복사하지 않도록 주의하세요.
‘게시’ 대신 ‘디자인에 사용’이 보여요

‘디자인에 사용’에서 웹사이트 형식을 선택하고, 편집기에 들어가 미리보기로 확인한 뒤 ‘웹사이트 게시’로 진행하세요. 화면이 공식 안내와 다르거나 게시 메뉴가 없다면 아래 도움말에서 현재 계정의 지원 상태를 확인합니다.

Canva 공식 게시 안내

나중에 바꿀 때는 원래 코드 대화로 돌아가 수정한 뒤 같은 사이트를 다시 게시하세요. 생성 화면의 수정만으로 공개 사이트가 바뀌었다고 판단하지 마세요.
07

학생 입장에서 열고 QR로 공유하기

이 단계가 끝나면: 실제 수업에 나눠 줄 주소와 QR을 확인했습니다.

  1. 시크릿 창이나 다른 기기에서 게시한 주소를 엽니다.
  2. 편집 권한 요청 없이 퀴즈가 열리고 마지막까지 풀리는지 확인합니다.
  3. 아래 QR 도구에 주소를 붙여넣고 QR을 띄웁니다.
  4. 휴대폰 카메라로 QR을 찍어 같은 퀴즈가 열리는지 확인합니다.

활동 안내에 “퀴즈 풀기 → 해설 확인 → 틀린 개념 다시 보기”를 함께 적으면 수업에 바로 활용하기 좋습니다.

01

무료 계정으로 접속하기

교사용 실습입니다. 학생에게 동일한 계정 접근이나 공유 권한이 있다고 가정하지 마세요. 오늘은 설치, API 키, 결제 정보가 필요 없습니다.

Canvas에서 만들고 미리보기

아래 프롬프트를 Canvas 채팅에 보내고, 오른쪽 미리보기에서 실행해 보세요.

05

오류 수정과 저장 연습하기

터미널에 주소가 한 줄 찍혀 있습니다. 그 주소를 마우스로 긁어 복사해 크롬 주소창에 붙여넣으면 됩니다.

② 배포는 됐는데 주소를 열면 Firebase 기본 안내 페이지가 보입니다.

index.html이 없는 폴더를 올렸거나, init에서 덮어쓰기(Overwrite)에 Y를 눌렀을 때 생깁니다. 위 표대로 다시 firebase init hosting을 실행하고 덮어쓰기에 N을 고른 뒤 다시 배포하세요.

③ Error: Failed to get Firebase project 라고 나옵니다.

콘솔에서 프로젝트를 아직 안 만들었거나, 다른 구글 계정으로 로그인돼 있을 때 나옵니다. firebase logout 후 firebase login으로 프로젝트를 만든 계정으로 다시 들어가세요.

문제 해결

자주 막히는 곳 10가지

연수 현장에서 실제로 가장 많이 나온 질문들입니다. 해당하는 항목을 눌러 펼쳐 보세요.

1. Codex에 글을 보냈는데 아무 반응이 없어요.

먼저 입력칸 오른쪽의 보내기(↑) 버튼을 눌렀는지 확인하세요. 화면에 ‘작업 중’ 표시가 보이면 정상입니다. 5분 넘게 같은 화면이면 “지금 어디까지 했어?”라고 한 번 더 보내세요.

2. 선택한 터미널 방식에서 command not found가 떠요.

“그런 이름의 프로그램을 못 찾겠습니다”라는 뜻입니다. 대부분 설치 직후 터미널을 새로 열지 않아서 생깁니다. 터미널 창을 완전히 닫고 새로 연 뒤 다시 쳐 보세요. 그래도 같다면 설치 명령어를 한 번 더 실행해 주시고, 설치할 때 오류 메시지가 없었는지 확인해 주세요.

3. 선택한 터미널 방식에서 한글이 깨져 보여요.

글자 저장 방식이 달라서 생기는 표시 문제입니다. 작업 자체에는 지장이 없습니다. Windows에서는 명령 프롬프트(cmd) 대신 Windows 터미널이나 PowerShell을 쓰시면 대부분 해결됩니다. 웹앱 화면의 한글이 깨진다면 그건 다른 문제이니, 도구에게 “한글이 깨져. 문자 인코딩을 UTF-8로 맞춰 줘. 다른 건 바꾸지 마.”라고 말씀하세요.

4. AI가 엉뚱한 걸 고쳤어요.

지시 범위가 넓었기 때문입니다. 먼저 “방금 수정 전으로 되돌려 줘.”라고 하신 뒤, 이번에는 고칠 곳을 하나만 집어 “○○만 바꿔 줘. 나머지는 그대로 둬.”라고 다시 요청하세요. 5단계의 범위 지정 원칙이 바로 이 문제를 막기 위한 것입니다.

5. 배포했는데 옛날 화면이 그대로 보여요.

캐시 때문입니다. 브라우저가 “아까 본 화면”을 저장해 두었다가 그대로 보여 주는 것입니다. Windows Ctrl+Shift+R · macOS ⌘+Shift+R 로 강력 새로고침해 보세요. 시크릿 창에서 열어 보시면 확실합니다. 학생들에게 안내하실 때도 이 방법을 알려주시면 좋습니다.

6. 학교 와이파이에서 설치나 로그인이 안 돼요.

학교·교육청 망이 외부 접속을 막는 경우가 많습니다. 가장 빠른 해결책은 휴대폰 핫스팟입니다. 설치와 로그인만 핫스팟으로 끝내고 다시 학교 와이파이로 돌아오셔도 됩니다. 계속 쓰셔야 한다면 정보부 선생님께 해당 주소의 차단 해제를 요청해 보세요.

7. 크레딧(사용량)이 떨어졌다고 나와요.

도구마다 일정 시간 동안 쓸 수 있는 양이 정해져 있습니다. 연수 중이라면 강사에게 알려 주세요. 혼자 하실 때는 잠시 뒤 다시 시도하시거나 구독 상태를 확인해 주세요. 아껴 쓰는 요령은 한 번에 하나씩, 짧고 구체적으로 요청하는 것입니다. 같은 지시를 여러 번 반복하는 것이 가장 많이 소모합니다.

8. 되돌리고 싶어요.

가장 간단한 방법은 도구에게 말하는 것입니다. “방금 수정 전으로 되돌려 줘.” 한 문장이면 됩니다. 중요한 순간에는 Codex의 변경 내역을 확인하거나 결과 파일을 따로 내려받아 보관하세요. 기존 폴더를 연결해 작업했다면 잘 되던 버전을 복사해 백업해도 됩니다.

9. 오늘 다 못 했는데, 다음에 이어서 하려면요?

다음에 ChatGPT 앱을 열고 → Codex를 고르고 → 최근 작업에서 오늘 작업을 다시 열면 이어서 할 수 있습니다. 기존 폴더를 연결했던 작업은 같은 프로젝트에서도 찾을 수 있습니다. 설치와 로그인은 다시 하지 않으셔도 됩니다. 이 페이지의 진도 체크도 같은 브라우저에서 여시면 그대로 남아 있습니다.

10. 학생에게 써도 되나요? 개인정보가 걱정됩니다.

오늘 만든 것처럼 로그인이 없고 개인정보를 저장하지 않는 앱은 위험을 크게 줄일 수 있습니다. 그래도 학교의 개인정보·정보보안 지침을 먼저 확인하고, 다음 세 가지를 꼭 지켜 주세요. ① 학생 실명·사진·연락처를 서버로 보내지 않기, ② 주소는 누구나 열 수 있으므로 민감한 내용을 넣지 않기, ③ 학교에서 정식으로 운영하실 때는 정보부·관리자와 사전 협의하기. 걱정되는 기능이 있다면 아예 넣지 않는 쪽이 언제나 낫습니다.
