아래 순서대로만 따라오시면 됩니다. 각 단계마다 복사 버튼이 있으니 명령어를 손으로 타이핑하지 마시고 복사해서 붙여넣어 주세요. 단계를 마칠 때마다 맨 아래 “이 단계 완료”에 체크하시면 위쪽 진도 배지가 올라갑니다.

1

준비물 챙기기

5분

이 단계가 끝나면 이렇게 됩니다. 터미널 창이 열려 있고, node -v를 쳤을 때 숫자가 나오며, 바탕화면의 작업 폴더 안에 들어와 있는 상태가 됩니다.

실행 절차

  1. 준비물을 확인합니다. 노트북, 크롬 브라우저, 구글 계정(Firebase 가입용), 오늘 고른 도구의 계정 — 이렇게 네 가지입니다.
  2. Node.js를 설치합니다. nodejs.org에 접속해 LTS라고 적힌 버튼을 누르고, 내려받은 설치 파일을 실행합니다. 설치 화면에서는 아무것도 바꾸지 말고 기본값 그대로 “다음”만 누르시면 됩니다. LTS는 “오래 안정적으로 지원하는 버전”이라는 뜻입니다. 재부팅은 하지 않으셔도 되고, 대신 터미널을 새로 열어야 설치가 반영됩니다.
  3. 터미널을 엽니다. Windows 작업표시줄 검색창에 cmd를 입력하고 명령 프롬프트를 엽니다. macOS 우측 상단 돋보기(Spotlight)를 누르고 터미널을 입력해 엽니다.
  4. 설치가 잘 됐는지 확인합니다. 아래 명령어를 복사해 터미널에 붙여넣고 엔터를 누릅니다.
터미널 — 설치 확인
$ node -v npm -v v22.20.0 10.9.3

숫자가 나오면 성공입니다. 숫자가 위 예시와 달라도 전혀 문제되지 않습니다. 숫자 대신 'node'은(는) 내부 또는 외부 명령이 아닙니다 같은 문장이 나오면 아래 “막히면 여기”를 펴 보세요.

작업 폴더 만들고 그 안으로 들어가기

  1. 바탕화면에 폴더를 만듭니다. 바탕화면 빈 곳에서 마우스 오른쪽 버튼 → 새로 만들기 → 폴더 → 이름을 my-first-webapp으로 바꿔 주세요. (한글·띄어쓰기 없이 영문으로 지어야 나중에 문제가 없습니다.)
  2. 터미널에서 그 폴더로 이동합니다. cd는 “이 폴더로 들어가라(change directory)”는 뜻입니다. 가장 쉬운 방법: 터미널에 cd 까지만 입력하고 한 칸 띄운 뒤, 방금 만든 폴더를 마우스로 끌어다 터미널 창에 놓으면(드래그 & 드롭) 경로가 저절로 적힙니다. 그다음 엔터를 누르세요.
터미널 — 폴더로 이동
# Windows $ cd %USERPROFILE%\Desktop\my-first-webapp # macOS $ cd ~/Desktop/my-first-webapp

이동에 성공하면 터미널 왼쪽에 적힌 경로 끝이 my-first-webapp으로 바뀝니다. 그게 “지금 이 폴더 안에 있다”는 표시입니다.

nodejs.org/ko/download

Node.js 내려받기 화면은 이렇게 생겼습니다

Node.js (LTS) 내려받기 다운로드
Node.js (Current) — 이건 고르지 마세요

버튼이 두 개 보입니다. 반드시 LTS 쪽을 누르세요.

막히면 여기

① node를 쳤는데 “내부 또는 외부 명령이 아닙니다”라고 나옵니다.

설치가 끝난 뒤 터미널을 새로 열지 않아서 그렇습니다. 터미널 창을 완전히 닫고 다시 연 다음 한 번 더 쳐 보세요. 그래도 같다면 Node.js를 다시 설치해 주세요.

② cd 했더니 “지정된 경로를 찾을 수 없습니다”라고 나옵니다.

폴더 이름의 철자나 위치가 다를 때 나오는 문장입니다. 위의 드래그 & 드롭 방법으로 다시 해 보시면 경로가 정확히 채워집니다. OneDrive를 쓰시는 Windows라면 바탕화면 위치가 달라질 수 있어 특히 드래그 & 드롭이 안전합니다.

③ 터미널 글씨가 너무 작아 보이지 않습니다.

Windows Ctrl + 마우스 휠, macOS ⌘ + + 로 키우실 수 있습니다.

아직 도구를 고르지 않으셨습니다. STEP 0으로 올라가 도구를 먼저 골라 주세요. 아래 명령어는 Codex 기준으로 보여 드리고 있습니다.

실행 절차

로그인 승인 화면

브라우저가 저절로 열리면서 이런 화면이 뜹니다

계정으로 로그인
터미널에서 이 계정을 사용하도록 허용하시겠습니까? 승인

승인을 누르면 브라우저에 “이제 터미널로 돌아가세요”라는 안내가 뜹니다. 브라우저는 닫으셔도 됩니다.

“권한을 물어보면 어떻게 하나요?”

실습 도중 Allow? Yes / No 같은 물음이 계속 나옵니다. 겁내지 않으셔도 됩니다. 이건 도구가 “제가 이 파일을 고쳐도 될까요?”라고 묻는 것입니다. 학생이 “선생님, 제 공책에 이거 적어도 돼요?”라고 묻는 것과 같습니다.

  • 오늘 실습 폴더 안에서 묻는 것은 모두 “예”로 답하셔도 안전합니다. 내 컴퓨터의 다른 파일은 건드리지 않습니다.
  • 화살표 키(↑↓)로 고르고 Enter로 선택합니다. 마우스로는 눌리지 않습니다.
  • 낯선 폴더나 인터넷 어딘가에 무언가를 보내겠다고 하면 그때는 “아니오”를 고르고 강사에게 알려주세요.
막히면 여기

① command not found 또는 “내부 또는 외부 명령이 아닙니다”

설치는 됐지만 터미널이 아직 모르는 상태입니다. 터미널을 완전히 닫고 새로 연 뒤 실행 명령어를 다시 쳐 보세요. 그래도 같다면 설치 명령어를 한 번 더 실행해 주세요.

② macOS에서 permission denied / EACCES 권한 오류

설치 폴더에 쓸 권한이 없을 때 납니다. 맨 앞에 sudo 를 붙여 다시 실행하시고, 물어보는 비밀번호는 맥 로그인 비밀번호입니다. (비밀번호는 화면에 안 보이는 게 정상입니다. 그냥 치고 엔터를 누르세요.)

③ 학교망·사내망에서 설치가 멈추거나 오류가 납니다

학교 방화벽이 막는 경우가 많습니다. 휴대폰 핫스팟으로 잠깐 바꿔 설치하시면 대부분 해결됩니다. 설치가 끝나면 다시 학교 와이파이로 돌아오셔도 됩니다.

설치 방법이 바뀔 수 있으니 막히면 공식 문서를 함께 확인해 주세요 → 공식 문서 열기

3

무엇을 만들지 정하기

7분

이 단계가 끝나면 이렇게 됩니다. 복사 버튼만 누르면 바로 쓸 수 있는 내 수업용 프롬프트 한 덩어리가 완성됩니다.

① 오늘 만들 앱을 하나 고르세요

② 프롬프트 빌더 — 빈칸만 채우세요

아래 칸을 채우면 오른쪽(모바일에서는 아래쪽) 상자의 프롬프트가 실시간으로 완성됩니다.

완성된 프롬프트
빈칸을 채우면 여기에 프롬프트가 나타납니다.

좋은 프롬프트의 4가지 습관

  1. 번호로 쪼개기 — 원하는 기능을 1, 2, 3으로 나눠 적습니다.
  2. 대상 명시 — “중학교 2학년이 씁니다”처럼 누가 쓰는지 밝힙니다.
  3. 금지사항 명시 — “로그인은 넣지 마세요”처럼 하지 말 것을 적습니다.
  4. 범위 지정 — “이것만 바꿔 주세요”라고 고칠 곳을 한정합니다.
만들기 전 ARCS 자가점검 4문항

“이 앱이 정말 학생을 움직이게 하는가”를 만들기 전에 스스로 점검해 보세요.

막히면 여기

① 무엇을 만들지 도무지 정해지지 않습니다.

고민하지 마시고 “단원 퀴즈 게임”을 고르세요. 가장 짧은 시간에 끝나고, 오늘 배운 방법 그대로 다른 앱으로 바꾸실 수 있습니다.

② 프롬프트가 너무 길어 보입니다.

길어도 괜찮습니다. 짧고 막연한 지시가 엉뚱한 결과를 만듭니다. 구체적인 문장이 길수록 결과가 좋아집니다.

③ 문제 내용까지 AI가 만들어도 되나요?

초안은 맡기시되 사실 확인은 반드시 선생님이 하셔야 합니다. 연도·인명·수치는 특히 틀리기 쉽습니다. 프롬프트에도 “확실하지 않으면 빈칸으로 두라”는 조건을 넣어 두었습니다.

첫 프로토타입 만들기

15분

이 단계가 끝나면 이렇게 됩니다. 폴더 안에 index.html 파일이 생기고, 그 파일을 더블클릭하면 브라우저에서 내 앱이 실제로 움직입니다.

실행 절차

  1. 터미널에서 도구를 실행합니다. (2단계에서 이미 켜 두셨다면 그대로 두세요.)
  2. 3단계에서 복사한 프롬프트를 붙여넣습니다. Windows Ctrl+V · macOS ⌘+V
  3. 엔터를 누르고 기다립니다. 보통 2~5분 걸립니다. 중간에 끄지 마세요.
  4. “파일을 만들어도 될까요?” 하고 물으면 “예”를 고릅니다. 화살표 키로 고르고 엔터입니다.
  5. 다 됐다고 하면 결과를 확인합니다. 아래 “결과 확인하는 두 가지 방법”을 보세요.

$ codex › 여기에 3단계 프롬프트를 붙여넣고 엔터를 누르세요

localhost는 “내 컴퓨터 안에서만 보이는 주소”입니다. 아직 학생은 못 봅니다. 학생에게 보여 주는 일은 6단계에서 합니다.

막히면 여기

① 한참을 기다려도 아무 반응이 없습니다.

대개 승인 물음에 답을 안 한 상태입니다. 화면 맨 아래를 보시고 Enter를 한 번 눌러 보세요. 그래도 멈춰 있으면 Ctrl+C로 멈춘 뒤 도구를 다시 실행하고 프롬프트를 한 번 더 붙여넣으시면 됩니다.

② 프롬프트를 붙여넣었더니 줄이 이상하게 잘립니다.

③ 파일이 어디에 만들어졌는지 모르겠습니다.

터미널이 현재 있는 폴더에 만들어집니다. 1단계에서 cd로 들어간 my-first-webapp 폴더를 바탕화면에서 열어 보세요.

3분

이 단계가 끝나면 이렇게 됩니다. 화면에 큼직한 QR코드가 떠 있고, 학생들이 휴대폰을 비추기만 하면 선생님의 앱이 열립니다.

https://까지 통째로 붙여넣으시면 됩니다. 주소를 입력하는 순간 오른쪽에 QR이 만들어집니다.

QR은 선생님 브라우저 안에서 만들어집니다. 주소가 외부로 전송되지 않습니다.

주소를 입력하면 QR이 여기에 나타납니다.

이 페이지를 못 쓰는 상황이라면

크롬에서 내 웹앱 주소를 연 다음, 화면 빈 곳에서 마우스 오른쪽 버튼 → “이 페이지의 QR 코드 생성”을 누르셔도 같은 QR이 나옵니다. 주소창 오른쪽 끝의 공유 아이콘에서도 찾으실 수 있습니다.

수업에 이렇게 써 보세요

도입부 동기유발

수업 시작 3분, QR을 띄워 두고 “오늘 배울 내용, 지금 몇 개나 아는지 봅시다”로 여는 방법입니다.

모둠 활동

모둠에 한 대씩 띄워 두고 협력해서 풀게 합니다. 모둠별 점수를 칠판에 적으면 몰입도가 올라갑니다.

수행평가 보조

연습 단계에 쓰고, 결과 화면을 캡처해 제출하게 합니다. 평가 자체보다 연습 도구로 쓰실 때 부담이 적습니다.

막히면 여기

① QR이 안 만들어집니다.

주소가 https://로 시작하는지 확인해 주세요. my-first-webapp.web.app처럼 앞부분이 빠지면 만들어지지 않습니다.

② 학생 휴대폰에서 QR이 잘 안 읽힙니다.

프로젝터 화면이 작거나 흐릴 때 그렇습니다. 전면 송출하기 버튼으로 화면 가득 키우시고, 교실 조명을 조금 낮춰 보세요.

③ 학생 기기에 인터넷이 없습니다.

배포된 앱은 인터넷이 있어야 열립니다. 학교 와이파이 비밀번호를 함께 안내하시거나, 모둠에 한 대씩만 접속하게 하는 방식으로 운영해 보세요.

문제 해결

자주 막히는 곳 10가지

연수 현장에서 실제로 가장 많이 나온 질문들입니다. 해당하는 항목을 눌러 펼쳐 보세요.

1. 명령어를 쳤는데 아무 반응이 없어요.

두 가지 경우입니다. 첫째, 엔터를 안 누르셨습니다. 명령어를 붙여넣은 뒤 반드시 엔터를 눌러야 실행됩니다. 둘째, 실행 중이라 기다리는 중입니다. 설치는 1~3분, 앱 제작은 2~5분 걸립니다. 커서가 깜빡이고 있으면 정상이니 기다려 주세요. 5분이 넘도록 변화가 없으면 Ctrl+C로 멈추고 다시 시작하시면 됩니다.

2. command not found / “내부 또는 외부 명령이 아닙니다”가 떠요.

“그런 이름의 프로그램을 못 찾겠습니다”라는 뜻입니다. 대부분 설치 직후 터미널을 새로 열지 않아서 생깁니다. 터미널 창을 완전히 닫고 새로 연 뒤 다시 쳐 보세요. 그래도 같다면 설치 명령어를 한 번 더 실행해 주시고, 설치할 때 오류 메시지가 없었는지 확인해 주세요.

3. 터미널에서 한글이 깨져 보여요.

글자 저장 방식이 달라서 생기는 표시 문제입니다. 작업 자체에는 지장이 없습니다. Windows에서는 명령 프롬프트(cmd) 대신 Windows 터미널이나 PowerShell을 쓰시면 대부분 해결됩니다. 웹앱 화면의 한글이 깨진다면 그건 다른 문제이니, 도구에게 “한글이 깨져. 문자 인코딩을 UTF-8로 맞춰 줘. 다른 건 바꾸지 마.”라고 말씀하세요.

4. AI가 엉뚱한 걸 고쳤어요.

지시 범위가 넓었기 때문입니다. 먼저 “방금 수정 전으로 되돌려 줘.”라고 하신 뒤, 이번에는 고칠 곳을 하나만 집어 “○○만 바꿔 줘. 나머지는 그대로 둬.”라고 다시 요청하세요. 5단계의 범위 지정 원칙이 바로 이 문제를 막기 위한 것입니다.

5. 배포했는데 옛날 화면이 그대로 보여요.

캐시 때문입니다. 브라우저가 “아까 본 화면”을 저장해 두었다가 그대로 보여 주는 것입니다. Windows Ctrl+Shift+R · macOS ⌘+Shift+R 로 강력 새로고침해 보세요. 시크릿 창에서 열어 보시면 확실합니다. 학생들에게 안내하실 때도 이 방법을 알려주시면 좋습니다.

6. 학교 와이파이에서 설치나 로그인이 안 돼요.

학교·교육청 망이 외부 접속을 막는 경우가 많습니다. 가장 빠른 해결책은 휴대폰 핫스팟입니다. 설치와 로그인만 핫스팟으로 끝내고 다시 학교 와이파이로 돌아오셔도 됩니다. 계속 쓰셔야 한다면 정보부 선생님께 해당 주소의 차단 해제를 요청해 보세요.

7. 크레딧(사용량)이 떨어졌다고 나와요.

도구마다 일정 시간 동안 쓸 수 있는 양이 정해져 있습니다. 연수 중이라면 강사에게 알려 주세요. 혼자 하실 때는 잠시 뒤 다시 시도하시거나 구독 상태를 확인해 주세요. 아껴 쓰는 요령은 한 번에 하나씩, 짧고 구체적으로 요청하는 것입니다. 같은 지시를 여러 번 반복하는 것이 가장 많이 소모합니다.

8. 되돌리고 싶어요.

가장 간단한 방법은 도구에게 말하는 것입니다. “방금 수정 전으로 되돌려 줘.” 한 문장이면 됩니다. 더 확실하게 하고 싶으시면, 잘 되던 순간에 폴더를 통째로 복사해 my-first-webapp-백업처럼 이름 붙여 두세요. 오늘 수준에서는 이게 가장 쉽고 안전한 방법입니다.

9. 오늘 다 못 했는데, 다음에 이어서 하려면요?

폴더만 그대로 두시면 됩니다. 다음에 터미널을 열고 → cd로 그 폴더에 들어가서 → 도구를 다시 실행하시면 이어집니다. 설치와 로그인은 다시 하지 않으셔도 됩니다. 이 페이지의 진도 체크도 같은 브라우저에서 여시면 그대로 남아 있습니다.

10. 학생에게 써도 되나요? 개인정보가 걱정됩니다.
