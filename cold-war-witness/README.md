# 냉전의 목격자 — 감시 속에서 내리는 선택

냉전 시대를 살아가는 **평범한 시민(가상 인물)** 이 되어 선택을 내리고, 그 경험을 근거로 모둠이 **AI 윤리 콘텐츠**(숏폼·웹툰·카드뉴스·굿즈·포스터)를 기획·창작·발표하는 중학교 2학년 역사 **6차시 프로젝트 수업**용 웹앱입니다. 모든 차시에서 앱을 씁니다.

- 출품: 2026 인공지능 윤리교육 콘텐츠 공모전 (주최: 과학기술정보통신부·정보통신정책연구원)
- 개발: 동쌤 김동은 (번동중학교)
- 교과: 중학교 역사① (2022 개정) [9역07-01] [9역07-02] · 한국형 사회정서교육 교육과정(2025) 연계
- 윤리원칙: 「대한민국 인공지능 윤리원칙」(2026. 8. 21., 관계부처 합동) 3대 가치 + 7대 원칙 + 원칙별 세부 항목과 ‘이용자’ 역할 — 원문 그대로 수록

**수업: 디지털 인공지능 윤리 콘텐츠 창작 및 발표 수업 (6차시)**

| 수업 개요 | 차시 | 앱 활동 | K-SEL 성취기준 |

## 1. 무엇이 들어 있나요

**학생 화면**
- 입장: 학급 코드 → 번호·닉네임 → PIN 4자리 (실명·이메일·전화번호를 받지 않음, 익명 로그인)
- 다른 기기에서 이어 하기: 학급 코드 + 번호 + PIN
- **6차시 로드맵**: 선생님이 연 차시까지의 활동이 열림(지난 차시 활동은 계속 열려 있음)
- **활동 안내**(1차시): 미션, 6차시 흐름, 콘텐츠 형식, 3대 가치·7대 원칙, ‘AI 이용자’ 원문 정의, 평가 기준, 모둠의 4가지 약속
- **우리 모둠**(1차시): 모둠 고르기·옮기기(최대 6명), 강점에 맞는 역할 고르기(5가지 역할, 1인 최대 2개, 빈 역할 표시), 모둠 이름·약속, 사건 파일 고르기
- **기획서**(2~3차시): 모둠원이 함께 쓰는 공동 기획서(칸마다 자동 저장, 친구가 쓴 내용 실시간 반영) — 제목·대상·형식·근거 사실 카드·오늘날 AI 문제·중심 원칙과 세부 항목·3대 가치·핵심 메시지·구성·도구·생성형 AI 활용 계획·역할별 할 일, **윤리 점검표**(근거 = 원문 ‘이용자’ 역할 문장), 제출 → 교사 승인/고칠 점
- **기획서 검토**(3차시): 다음 번호 모둠의 기획서에 칭찬·제안·윤리 의견, 받은 피드백 보기
- **창작 작업실**(4~5차시): 진행 단계, 형식별 스토리보드 칸, **AI 활용 기록**(도구·쓴 곳·사람이 한 일·표기 문구 추천), 출처, **최종 윤리 점검** 후 작품 링크 제출(파일은 앱에 올리지 않음)
- **발표·피드백**(6차시): 다른 모둠 작품 보기, 루브릭 4항목 별점 + 칭찬·제안(이름 없이 전달), 우리 모둠이 받은 평균 별점과 피드백
- 사건 파일: 인트로 → 장면 1~5 (감정 체크 → 선택 → 선택 결과 → “실제 역사에서는?” 사실 카드) → AI 시대 연결 성찰 → 원칙 카드 획득 → 챕터 마무리(학급 선택 분포, 마음 돌아보기) → 완료 도장
- 쓰기 칸마다 글자 수 표시와 **문장 시작 도우미**(누르면 칸에 들어가는 첫 마디)
- 원칙 카드 도감 + **원문 살펴보기**(7대 원칙 원문·세부 항목·이용자 역할), 선언문(카드 보드 + 3대 가치 + 우리 모둠 작품), 인증서(모둠 작품·내 역할 포함, 인쇄·이미지 저장)
- 진행은 장면마다 자동 저장, 선택에는 점수·정답 없음

**선생님 화면**
- Google 로그인, 여러 학급 만들기(6자리 코드 자동 발급)
- 수업 진행: **지금 차시 1~6** 단추(그 차시 수업 흐름 보기 포함), **모둠 수**(0~8), 선택 분포 학생 공개
- 탭: **모둠 현황**(모둠원·역할·빈 역할·사건 파일·기획서 상태·점검·제작 단계·제출) · **기획서 검토**(기획서·미체크 문항·동료 검토 → 승인/고칠 점) · **발표·평가**(평균 별점·피드백, 모둠 발표 화면) · 개인 현황(모둠 옮기기) · 선택 분포 · 성찰·선언문(⭐ 하이라이트·발표 모드) · 학급 관리
- CSV 내보내기(학생별 · **모둠별**), 학생 PIN 초기화(임시 PIN), 학급 삭제(두 번 확인, 모둠·평가까지 데이터 파기)
- 수업 자료: **6차시** 교수·학습 과정안, 차시별 활동지(역할 분담표·기획서 양식·윤리 점검표·스토리보드·AI 활용 기록·평가표), 교사용 가이드, 교육과정·AI 윤리원칙 연계표 (A4 인쇄·PDF 저장)

**디자인**: Tailwind CSS 4 + **daisyUI 5 ‘cupcake’ 테마**(귀엽고 화사한 파스텔) · **lucide 아이콘** · **Pretendard 글꼴**(앱과 함께 배포 — 외부 글꼴 서버 없이 학교망에서도 빠름). 감정 체크 5종은 표정이 잘 드러나도록 이모지를 그대로 씁니다.

**기술**: Vite + React 18 + TypeScript + Tailwind CSS 4 + daisyUI 5 · Firebase(Authentication, Cloud Firestore, Hosting) — **무료 Spark 요금제만 사용**. Cloud Functions·유료 기능·외부 AI API·외부 분석 도구(GA 등) 없음.

## 2. Firebase 설정 — 선생님이 콘솔에서 할 일

> 처음 한 번만 하면 됩니다. 20분 정도 걸려요.

### 2-1. 프로젝트 만들기
1. <https://console.firebase.google.com> 에 Google 계정으로 로그인합니다.
2. **프로젝트 추가** → 이름 입력 (예: `cold-war-witness`) → **Google 애널리틱스는 끕니다**(학생 개인정보 보호).
3. 요금제는 **Spark(무료)** 그대로 둡니다.

### 2-2. 로그인 방법 켜기 (Authentication)
1. 왼쪽 메뉴 **빌드 → Authentication → 시작하기**
2. **로그인 방법** 탭에서 두 가지를 **사용 설정**합니다.
   - **Google** (선생님용) — 프로젝트 지원 이메일을 고르고 저장
   - **익명** (학생용)
3. **설정 → 승인된 도메인**에 배포 주소(`프로젝트ID.web.app`, `프로젝트ID.firebaseapp.com`)가 있는지 확인합니다. 다른 주소로 쓰면 여기에 추가합니다.

### 2-3. 데이터베이스 만들기 (Firestore)
1. **빌드 → Firestore Database → 데이터베이스 만들기**
2. 위치: **`asia-northeast3` (서울)** — 나중에 바꿀 수 없어요.
3. **프로덕션 모드**로 시작합니다. (보안 규칙은 3단계에서 배포합니다.)

### 2-4. 웹 앱 등록 → 설정값 복사
1. **프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹(`</>`)** 으로 앱을 추가합니다. (Hosting 설정 체크는 하지 않아도 됩니다.)
2. 나오는 `firebaseConfig` 값을 `cold-war-witness/.env.local` 파일에 옮겨 적습니다.

```bash
cd cold-war-witness
cp .env.example .env.local
# .env.local 을 열어 아래 값을 채웁니다
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=프로젝트ID.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=프로젝트ID
VITE_FIREBASE_STORAGE_BUCKET=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
VITE_USE_EMULATOR=
```

> 이 값들은 비밀번호가 아니라 “어느 프로젝트에 연결할지” 알려 주는 주소입니다. 데이터는 보안 규칙이 지킵니다. 그래도 `.env.local` 은 git 에 올라가지 않게 되어 있습니다.

### 2-5. 프로젝트 ID 연결
`cold-war-witness/.firebaserc` 의 `"default"` 값을 내 프로젝트 ID 로 바꿉니다.

```json
{ "projects": { "default": "내-프로젝트-ID" } }
```

## 3. 배포하기

컴퓨터에 **Node.js 20 이상**이 있어야 합니다.

```bash
cd cold-war-witness
npm install
npx firebase login            # 처음 한 번 (브라우저가 열리면 같은 Google 계정으로 로그인)
npm test                      # 콘텐츠·계산 점검 (42개 통과해야 함)
npm run deploy                # = 빌드 + Hosting 배포 + Firestore 보안 규칙 배포
```

끝나면 `https://프로젝트ID.web.app` 주소가 나옵니다. 이 주소를 학생에게 알려 주세요.

**배포 뒤 꼭 확인할 것**
1. 선생님 화면에서 Google 로그인이 되는지 (팝업이 막히면 주소창 오른쪽에서 팝업 허용)
2. 학급을 만들고 모둠 수를 정한 뒤, 다른 기기(또는 시크릿 창)에서 학생으로 입장해 모둠을 골라 보기
3. 선생님 화면 ‘모둠 현황’에 그 학생이 보이는지

> 보안 규칙만 다시 올리려면: `npx firebase deploy --only firestore:rules`

## 4. 수업에서 쓰기

자세한 발문·예상 반응·유의점은 앱의 **선생님 화면 → 수업 자료 → 교사용 가이드**에 있습니다(인쇄 가능).

1. **수업 전**: 학급 만들기 → 학급 코드를 칠판에 적기 → 인쇄 자료(과정안·활동지) 준비 → 결과물을 올릴 곳(학교 계정 드라이브·학급 게시판 등) 정하기 → 생성형 AI 사용 가능 여부(학교 방침·서비스 연령 기준) 확인
2. **1차시**: 모둠 수 정하기 → 학생: 활동 안내 → 우리 모둠(역할·약속·사건 파일) → ‘모둠 현황’에서 빈 역할 확인
3. **2차시**: ‘지금 차시’ 2 → 학생: 모둠 사건 파일 체험(약 20분) → 기획서 시작 → ‘선택 분포’를 화면에 띄워 토론
4. **3차시**: ‘지금 차시’ 3 → 학생: 기획서 완성·윤리 점검·제출 → 다른 모둠 검토 → 교사: ‘기획서 검토’에서 승인 또는 고칠 점
5. **4~5차시**: 학생: 창작 작업실(스토리보드·AI 활용 기록·출처) → 5차시에 최종 점검 후 작품 링크 제출 → ‘모둠 현황’에서 제출 확인
6. **6차시**: ‘발표·평가’ → **모둠 발표 화면**으로 한 모둠씩 발표 → 학생: 발표·피드백 화면에서 상호 평가 → 실천 선언문·인증서
7. **학기 끝**: ‘학급 관리’ → 학생별·모둠별 CSV 내려받기 → **학급 삭제**(데이터 파기)

**학생이 PIN 을 잊었을 때**: ‘학급 관리 → PIN 초기화’ → 화면에 나온 임시 PIN 을 알려 주면, 학생은 ‘다른 기기에서 이어 해요’로 들어옵니다. 기록은 그대로 남아요.

**선택 분포 공개는 선생님 화면이 열려 있을 때 갱신됩니다.** (서버 기능 없이 무료로 운영하기 위해, 선생님 화면이 숫자를 모아 올립니다.)

## 5. 문장 고치기 (코드를 몰라도 됨)

역사 콘텐츠와 수업 자료는 모두 `src/data/` 에 있습니다. 따옴표 안의 문장만 고치면 됩니다.

| 고칠 것 | 파일 |
|---|---|
| 차시·역할·콘텐츠 형식·기획서 항목·윤리 점검표·루브릭·약속 | `src/data/project.ts` |
| 장면 본문·선택지·결과·성찰 질문·문장 시작 도우미 | `src/data/scenarios.ts` |
| 사실 카드와 출처 | `src/data/facts.ts` |
| 원칙 카드 설명·냉전 연결 한 줄·3대 가치 (원문 문장은 고치지 않기) | `src/data/principles.ts` |
| 교육과정 원문(성취기준·K-SEL 역량) | `src/data/curriculum.ts` |
| 과정안·활동지·교사용 가이드 | `src/data/lessonMaterials.ts` |
| 앱 정보(공모전) 페이지 | `src/data/appInfo.ts` |
| 감정 체크 5종 | `src/data/emotions.ts` |
| 앱 제목 | `src/config.ts` 의 `APP_TITLE` |

**지켜 주세요**
- 사건·날짜·수치·실존 인물의 행동은 사실 카드(`facts.ts`)에만 씁니다. 실존 인물의 말은 따옴표로 직접 인용하지 않습니다.
- `id`(예: `ch1-s1`, `ch1-q1`, `'a'`, 역할 `leader`, 점검 문항 `hc1`, 사실 카드 `c1-files`)는 저장 데이터·보안 규칙과 이어져 있어 바꾸면 안 됩니다. 장면·질문·사실 카드·점검 문항을 **추가**하려면 `firestore.rules` 의 id 목록도 같이 고쳐야 합니다(`npm test` 가 알려 줌).
- 고친 뒤 `npm test` → 통과하면 `npm run deploy`

`npm run facts:doc`, `npm run curriculum:doc` 로 검토용 표(`docs/fact-cards.md`, `docs/curriculum-map.md`)를 다시 만들 수 있습니다.

## 6. 개발·테스트

```bash
npm install
npm run emulators      # 터미널 1: 로컬 Firebase 에뮬레이터 (Auth 9099, Firestore 8080)
npm run dev:emu        # 터미널 2: 에뮬레이터에 붙은 개발 서버 http://localhost:5173
```

| 명령 | 내용 |
|---|---|
| `npm test` | 콘텐츠 구조 점검 + 계산 함수 단위 테스트 (42개) |
| `npm run test:rules` | **보안 규칙 테스트** — 에뮬레이터를 스스로 켜고 끔 (60개) |
| `npm run e2e` | 브라우저 6차시 전체 흐름(교사 1 · 학생 2 · 모둠 2) + 키보드 조작 + 접근성(axe, WCAG 2.1 AA) 점검. 에뮬레이터와 `dev:emu` 가 켜져 있어야 함. 처음 한 번 `npx playwright install chromium` |
| `npm run build` | 타입 검사 + 배포용 빌드 |

에뮬레이터 개발 중 선생님 로그인은 Google 대신 에뮬레이터의 가짜 계정 화면이 뜹니다(“Add new account”).

## 7. 개인정보·보안

- 학생: 익명 로그인 + 번호 + 닉네임. 실명·이메일·전화번호를 받지 않습니다. 입장 화면에 “실명 대신 번호와 닉네임만 입력하세요” 안내.
- **PIN 은 원문을 저장하지 않습니다.** 학생 기록의 문서 주소가 `SHA-256(앱 고유 문자열:학급:번호:PIN)` 이라서, PIN 을 아는 사람만 그 기록을 찾아 다른 기기로 옮길 수 있습니다.
- 보안 규칙(`firestore.rules`): 학생은 자기 기록만, 교사는 자기가 만든 학급만. 모둠 기록은 **그 모둠 학생만** 고치고(명단은 자기 칸만, 기획서 승인은 교사만), 같은 학급 학생은 읽기만. 검토·평가는 보낸 사람·받은 모둠·교사만 읽음. 학급 코드는 한 건 조회만(목록 조회 금지). 모든 쓰기에서 필드 이름·타입·길이 검증(서술형 최대 500자). 한 번 고른 선택·감정은 바꿀 수 없음.
- 학급 삭제 시 학생 기록·자리·멤버·모둠·검토·평가·통계·하이라이트·코드·학급을 모두 지웁니다.
- 작품 파일은 앱에 올리지 않고 링크(https)만 저장합니다. (Cloud Storage 는 유료 요금제가 필요하고, 학생 얼굴·목소리 같은 개인정보가 앱에 쌓이지 않게 하기 위해)
- 외부 분석 도구·광고·외부 AI 호출 없음. 보안 헤더(CSP 등)를 `firebase.json` 에 설정.

## 8. 알려진 한계

- **PIN 은 4자리**라서, 같은 반 학생이 작정하고 1만 번을 시도하면 뚫릴 수 있습니다(서버 기능 없이는 시도 횟수를 막을 수 없음). 의심되면 PIN 초기화로 바로 막을 수 있습니다.
- **번호를 잘못 골라 들어온 학생**의 기록을 선생님이 지우는 기능은 명세에 없어 넣지 않았습니다. (제안: `docs/work-log.md`)
- **선택 분포 학생 공개**는 선생님 화면이 열려 있는 동안 갱신됩니다.
- 무료 요금제 한도(하루 읽기 5만·쓰기 2만): 모둠 기록은 입력을 멈추고 2초 뒤에 저장하고, 학생은 **자기 모둠 문서만** 실시간으로 받아 읽기를 줄였습니다. 30명 학급 한 차시 ≈ 쓰기 1,500회·읽기 1만 회 안팎(어림). 하루에 여러 학급이 같은 프로젝트에서 동시에 기획·창작하면 한도에 가까워질 수 있습니다(docs/data-model.md 6장).
- 모둠원이 **같은 칸**을 동시에 고치면 나중에 저장한 글이 남습니다. 칸을 나눠 맡도록(칸 옆 ‘주로 맡을 역할’) 안내해 주세요.
- 참고 블로그·KISDI 공모 페이지는 이전 작업 환경에서 열 수 없어, 수업 형식은 일반적인 프로젝트 수업 형식으로 만들었습니다.
