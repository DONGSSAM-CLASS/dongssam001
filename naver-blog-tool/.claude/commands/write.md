# /write — 블로그 초안 작성

사용자 메모: $ARGUMENTS

CLAUDE.md의 절대 규칙·글쓰기 공식·자가 검증 원칙을 전부 따른다. 순서대로 진행하고, 각 단계는 "됐는지 확인했다"로 끝낸다.

## 1. 자료 읽기
- `data/profile.md`, `data/blogger-profile.md`, `data/authority-lines.md`, `data/photo-guide.md`, `data/trends.md`, `data/style-profile.md`, `data/post-log.md`를 읽는다.
- `input/photos/`(하위 `_mosaic/` 제외)와 `input/videos/` 목록을 확인한다. 사진이 없으면 사용자에게 넣어 달라고 하고 멈춘다.
- **모든 사진을 Read로 직접 본다.** 사진마다: 무엇이 보이는지, 읽히는 글자(공고 제목·게시일·메뉴 경로·버튼·금액), 스토리상 위치, 개인정보 여부를 메모한다.

## 2. 빠진 정보 묻기 (지어내지 않는다)
- **협찬 여부**: 메모에 없으면 반드시 질문 (무료 이용권·제휴 링크 포함). 협찬이면 대가 유형과 업체 지정 문구 여부도.
- 동쌤이 **직접 해 본 것인지** (경험형 vs 정리형 서술이 갈림), 공개해도 되는 숫자(환급액 등)가 있는지.
- 메인 키워드 후보 2~3개를 제안하고 고르게 한다 (지자체 제도면 서울/경기 지역명 포함, 연도 포함 여부).
- 질문은 한 번에 모아서. 답을 받으면 새로 확인된 사실은 `data/profile.md`에 기록.

## 2-1. 공식 출처 확보 (돈 정보 글 필수)
- 주제의 1차 출처(기관 공고·안내 페이지)를 찾아 WebFetch 로 읽고, CLAUDE.md "생활 돈 정보 체크리스트" 항목을 채운다. 차단되면 사용자에게 공고 원문/캡처 요청.
- 본문에 쓸 모든 숫자·날짜·자격을 `facts` 에 등록하고, 출처로 확인한 것만 `verified: true` + `evidence`. (자세한 절차는 `/verify-facts`)
- 올해 공고가 아직 없으면 사용자에게 알리고: ① 작년 기준 명시 후 발행, ② 공고 후 발행 중 고르게 한다.

## 3. 개인정보 모자이크 (해당 시)
- 발견 내역(사진·영역·사유)을 사용자에게 알리고 승인받는다.
- spec → `node scripts/mosaic.js drafts/<초안명>.mosaic.json` → 처리본을 Read로 열어 확인 → 덜 가려졌으면 좌표 키워 재실행 → 초안엔 `_mosaic/` 경로.

## 4. 설계
- 페르소나 1명(지역·나이·직책·상황·감정), 메인/서브 키워드, 후킹 패턴(`post-log.md` 직전 3개와 다르게), 권위 문구(authority-lines.md, 사실 기반만), 사진 스토리 순서.

## 5. 초안 작성 → `drafts/YYYYMMDD-slug.json`
- CLAUDE.md 초안 JSON 포맷 그대로 (`postType: "money"`, `basisDate`, `sources`, `facts`). 협찬이면 첫 블록 = 협찬 표기 text 블록.
- 첫 소제목 앞에 "✔ 기간 / ✔ 대상 / ✔ 방법" 요약 체크리스트, 끝부분에 "자주 하는 실수"·Q&A 로 체류시간 확보.
- 광고 클릭 유도 문구 절대 금지. 동영상이 있으면 `video`, `place` 는 기본 null.
- 사진이 아직 없으면 `shotList` 에 필요한 캡처 목록을 적고, 사용자에게 캡처 요청.
- 작성 후 **`node scripts/check_draft.js drafts/<초안>.json`** 실행 → ❌오류 0개까지 수정. ⚠️경고는 고치거나 사유를 보고에 적는다.

## 6. 검수 보고 (채팅) — 승인 요청
`node scripts/preview_draft.js drafts/<초안>.json`으로 모바일 미리보기(`drafts/<초안>.preview.html`)를 만들어 경로를 알려 준다.
다음을 보여 주고 **"임시저장할까요?"**라고 묻는다. 승인 전에는 절대 임시저장하지 않는다.
- 제목 / 페르소나 / 메인·서브 키워드 / 후킹 패턴 / 권위 문구 유형
- 모바일에서 읽듯 본문 미리보기 (소제목·인용구 표시, 사진 위치는 `[사진: 파일명 — 캡션]`)
- check_draft 결과 요약 (글자 수, 키워드 횟수, 사진·인용구 수, 경고)
- 필수 정보 체크리스트 대조표 (✔/✘, ✘은 사유) + 사실 검증 현황 (검증 n/m, 미검증 항목)
- 모자이크 처리 내역, 협찬 표기 여부
- 자가 질문 답: "인용구와 소제목만 훑어도 핵심이 전달되는가?"
- 추가하면 좋은 사진 컷 (photo-guide.md 기준)

수정 요청을 받으면 반영 → check_draft 재실행 → 다시 보고. 말투·구성 관련 피드백은 `data/blogger-profile.md` "교정 피드백 누적 기록"에 남긴다.

## 7. 승인 후 임시저장
- 셀렉터를 최근에 고쳤거나 첫 실행이면 먼저 `node scripts/naver_draft.js drafts/<초안>.json --dry-run`.
- 본 실행: `node scripts/naver_draft.js drafts/<초안>.json`
- 로그 마지막 **"자동 처리 결과"** 블록을 읽는다. "대조검증"이 ✅가 아니면 성공 보고 금지 → `drafts/<초안>.dump.txt`와 초안을 비교해 원인 수정 (셀렉터 문제면 `probe_selectors.js`로 실측). 로그인 오류면 `/setup-login` 안내.
- 같은 초안 3회 실패 → `drafts/<초안>.manual.txt`를 주고 수동 붙여넣기 안내.

## 8. 완료 보고
- ❗수동 필요 항목만 안내 + 발행 체크리스트(발행 시간대, 24시간 수정 금지, 주 2~3회, 협찬 표기 육안 확인).
- "네이버 블로그 → 글쓰기 → 저장 글에서 확인 후 발행 버튼은 직접 눌러 주세요."
- 디버깅 재실행이 있었다면 "저장 글"에 쌓인 실패본을 직접 정리하도록 안내 (자동 삭제 금지).
- `data/post-log.md`에 한 줄 추가, `data/authority-lines.md` 사용 기록 추가.
- 새로 알게 된 교훈·해결책은 CLAUDE.md "트러블슈팅 기록"에, 안정 스크립트는 `.working.js`로 백업.
