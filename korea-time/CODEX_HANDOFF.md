# 인수인계 — 『Let's KOREA TIME』 : 중학생을 위한 고려로의 시간여행

2022 개정 역사과 교육과정과 연계한 **고려 시대 방탈출 추리 게임**.
중학교 3학년 역사 수업 한 차시(15~20분 플레이)용 웹 시뮬레이션.

제작자 표기: **동쌤(김동은 선생님)** — 메인 화면과 결과 화면 하단에 눈에 띄지 않게 들어가 있음.

## 2. 기술 스택 (제약)

- **순수 HTML + CSS + JavaScript (ES 모듈)**. **빌드 도구 없음.**
  - Vite·React·번들러·TypeScript 사용 **금지**. `index.html` 을 그대로 Hosting 에 올린다.
- 외부 라이브러리는 **Firebase JS SDK(gstatic CDN) 하나뿐**. 그 밖의 CDN·폰트·이미지 **금지**.
  - `firebase.json` 의 CSP 가 `script-src 'self' https://www.gstatic.com` 로 잠겨 있음.
- Firebase **Spark(무료) 요금제 범위만** 사용 — Authentication + Firestore + Hosting.
  - Cloud Functions · Cloud Storage 사용 **금지** (Blaze 필요). 서버 로직이 필요해 보이면 규칙과
    클라이언트로 해결한다. (비밀번호 초기화를 '세대' 방식으로 만든 이유가 이것)
- 이미지 파일 **없음**. 장면과 초상은 `js/art.js` 가 SVG 문자열로 생성한다.
  - 고려 시대 사진은 존재하지 않으므로, 실사처럼 보이는 이미지를 만들어 붙이지 않는다
    (학생이 진짜 사진으로 오해함). 실제 유적·유물의 형태에 근거한 연출 일러스트만 쓴다.
- ES 모듈이라 `file://` 로 열면 동작하지 않는다. 반드시 웹 서버로 연다.

## 4. 게임 구조 (반드시 유지할 설계)

### 4.1 흐름
```
시작 화면
  → (학생) 학급코드 가입/로그인  |  (교사) 이메일 로그인 → 대시보드
  → 수준 고르기 (중학생용 / 고등학생용)
  → [미션 1~6] 브리핑 → 대화 N개(단서 수집) → 자물쇠 3~4개 → 열쇠 조각 획득
  → 시간의 문 (마지막 암호)
  → 학습 결과 리포트 (성취기준 매핑 + 생각해 보기 질문)
```

미션은 **시대순으로 잠겨** 있다. `store.save.chapterIndex` 가 순서를 강제한다.

### 4.2 시대순 6개 미션과 성취기준

| # | 제목 | 시기 | 성취기준 | 장면 아트 | 조각 |
| --- | --- | --- | --- | --- | --- |
| 1 | 만월대의 잠긴 문서고 | 918~958 | `[9역10-01]` | `palace` | 開 |
| 2 | 압록강의 장막 | 993~1107 | `[9역10-02]` | `border` | 疆 |
| 3 | 흔들리는 개경 | 1126~1198 | `[9역10-02]` | `fire` | 亂 |
| 4 | 바다 건너 도읍, 강화 | 1231~1273 | `[9역10-02]` | `sea` | 抗 |
| 5 | 전하라 불린 폐하 | 1270~1366 | `[9역10-03]` | `yuan` | 革 |
| 6 | 벽란도의 하루 | 문화·생활 | `[9역10-04]` | `port` | 文 |

마지막 관문: 1장에서 얻은 **918** 과 6장에서 얻은 **1392** 를 빼서 **474**
(고려가 서 있던 햇수). `FINAL_GATE` 에 있다.

### 4.3 성취기준 편성 근거 — 문구를 지울 것

> 지금 학교에서 운영 중인 교육과정은 **2015 개정 교육과정**이지만,
> 2015 개정 교육과정이 **올해 안에 적용을 마치기 때문에** 이 자료를 내년 이후에도 계속
> 사용하고 널리 나눌 수 있도록 성취기준은 **2022 개정 역사과 교육과정**으로 편성했다.

이 문구는 `js/data/standards.js` 의 `CURRICULUM_NOTICE` 한 곳에 정의되어 있고,
시작 화면 안내 모달 · 결과 리포트 · 상태창의 성취기준 모달 · 교사 화면 안내에서 재사용된다.
**지우거나 2015 개정으로 바꾸지 말 것.**

### 4.4 난이도 (내용 동일, 친절함만 차등)

| | `ms` 중학생용 | `hs` 고등학생용 |
| --- | --- | --- |
| 힌트 | 처음부터 열림 | 두 번 틀려야 열림, 세 번 틀리면 자동 개방 |
| 문항 | 19개 | 25개 (`chapter.hsExtra` 가 장마다 1개 추가) |
| 브리핑 글 | `intro.ms` (길고 친절) | `intro.hs` (짧고 압축) |
| 낱말 풀이 | 동일하게 제공 | 동일하게 제공 |

**사료 원문과 해석, 퍼즐의 정답은 두 수준이 완전히 같다.** 수준을 나눈다고 역사 내용을
빼거나 쉬운 쪽에서 원문을 없애지 않는다.

### 4.5 퍼즐 설계 원칙 (가장 중요)

정답이 한눈에 보이면 안 된다. **여러 사료의 단서를 엮어야** 풀리게 만들어져 있다.
새 퍼즐을 만들 때도 이 원칙을 지킨다.

- 1장 둘째 자물쇠 — 『고려사』의 "광종 9년" + "광종 즉위 949년" → **958** 을 직접 계산
- 2장 — 소손녕의 요구와 서희의 반박을 견주어 담판의 **논리 순서**를 재구성 (ㄴ→ㄱ→ㄷ)
- 2장 셋째 — 거란이 "얻은 것과 내준 것"을 비교해 **숨은 목적**(송·고려 관계 단절) 추론
- 3장 둘째 — 만적이 말한 "경계(庚癸) 이래"를 간지로 풀어 **무신 정변(1170)** 을 지목
- 4장 셋째 — 처인성이 **부곡**이었고 김윤후가 **승려**였다는 두 사실을 엮어야 답이 보임
- 5장 첫째 — 원의 간섭 사례 중 **사실이 아닌 항목**("고려를 없애고 원의 성으로 삼았다",
  "과거제 폐지 강요")을 걸러내야 통과 → **고려는 독립국 지위를 유지했다**는 핵심을 확인
- 6장 둘째 — 검은 옷·검은 관·신·종이가 "소송할 수 있는 어른"의 표시라는 관습을 알아야
  손변 판결의 뜻이 풀림

선택지의 오답도 그럴듯하게 만들어 두었다. **"딱 봐도 틀린 보기"를 넣지 않는다.**

### 4.6 데이터 스키마

`js/data/chapters.js` 의 미션 하나:
```js
{
  id:'ch1', no:1, title:'…', place:'…', era:'918년 ~ 958년',
  standard:'9역10-01',          // standards.js 의 키여야 한다
  art:'palace',                  // art.js SCENE_KEYS 중 하나
  shard:{ glyph:'開', name:'개(開)', meaning:'…' },
  goal:'상태창에 뜨는 <지금 할 일>',
  intro:{ ms:'…', hs:'…' },      // 두 난이도 모두 필수
  beats:[{                       // 대화 = 단서 수집
    who:'최승로', role:'…', portrait:'scholar',   // art.js PORTRAIT_KEYS 중 하나
    lines:['…','…'],
    source:'siimu28',            // sources.js 의 키 → 대사 바로 밑에 사료 상자가 붙는다
    extraSources:['eumseo'],     // 선택
    clue:{ title:'…', text:'…' } // 단서 수첩에 쌓인다
  }],
  puzzles:[ /* 4.7 참고 */ ],
  hsExtra:{ /* 고등학생용 심화 1문항 */ },
  reward:{ record:'918 — …', note:'…' }   // 기록판(시간의 문 암호에 쓰임)
}
```

### 4.7 퍼즐 종류 4가지
```js
{ kind:'choice', options:[…], answer: 1 }              // 단일 선택, 정답 index
{ kind:'multi',  options:[…], answer: [1,2] }          // 복수 선택, 순서 무관
{ kind:'order',  options:[…], answer: [1,0,2] }        // 순서 배열, 0..n-1 의 순열이어야 함
{ kind:'input',  accept:['958','958년'] }              // 직접 입력, 공백·기호 무시하고 비교
// 공통: id, lock(자물쇠 이름), prompt, hint, explain(정답 해설), extraSources(선택)
```
`validate.mjs` 가 정답 범위와 순열 여부를 검사한다. 손으로 고쳤으면 반드시 돌린다.

### 4.8 사료 상자 (요구사항의 핵심)

**인물의 대사 바로 아래**에 이 순서로 붙는다. `ui.js` 의 `sourceBox()` 가 그린다.
```
사료 제목
원문        ← 한문 (확실한 것만)
원문 풀이    ← 국역
쉽게 말하면  ← 중1도 읽을 수 있는 수준
어려운 말 풀이 (접힘)  ← 낱말 사전
출처 · APA 양식
```
`sources.js` 의 한 항목:
```js
siimu28: {
  title:'…', original:'한문 원문', reading:'국역', easy:'쉬운 풀이',
  apa:'정인지, 김종서 외. (1451). 『고려사』 권93, 열전6, 최승로. 국사편찬위원회 한국사데이터베이스.',
  note:[['시무(時務)','지금 당장 해야 할 일.'], …],
}
```

**출처 규칙 (절대 지킬 것)**
- 출처는 **교과서가 아니라 실제 원전**을 적는다. `validate.mjs` 가 `apa` 에 "교과서"가
  들어가면 실패시킨다.
- 한문 원문이 확실하지 않으면 `original` 을 **비우고** `reading`(국역)만 싣는다.
  확인 안 된 한문을 지어 넣지 않는다.
- 모든 사료에 `apa` 와 `easy` 가 반드시 있어야 한다 (검사 항목).

## 5. 남은 일 — Firebase 배포

**현재 `js/firebase-config.js` 는 자리표시자이고, 그래서 앱이 '체험 모드'로 동작한다.**
(학급 기능 없이 혼자 플레이 가능, 진행은 그 브라우저에만 저장)

배포 절차:

1. Firebase 콘솔에서 프로젝트 생성 — https://console.firebase.google.com
   - **Authentication** → **이메일/비밀번호** 사용 설정
   - **Cloud Firestore** → 데이터베이스 만들기 → **프로덕션 모드**
   - 요금제 **Spark(무료)** 로 충분
2. 웹 앱(`</>`) 추가 → `firebaseConfig` 복사 → **`js/firebase-config.js` 에 붙여 넣기**
   (이 값들은 공개되어도 되는 주소다. 실제 보안은 `firestore.rules` 가 담당)
3. **`.firebaserc` 의 `"default"` 를 실제 프로젝트 아이디로** 바꾸거나 `firebase use --add`
4. 배포
   ```bash
   cd korea-time
   firebase deploy --only hosting,firestore:rules
   ```
5. 배포 후 실제 브라우저에서 확인
   - 교사 가입 → 학급 만들기 → 6자리 코드 확인
   - 다른 창에서 학생 가입(코드+번호+비밀번호+별명) → 1장 풀기
   - 교사 대시보드가 **실시간으로** 갱신되는지
   - 학생 창을 닫고 다시 로그인 → **이어서 진행되는지**
   - 대시보드 [비밀번호 초기화] → 같은 번호로 재가입 → **기록이 이어지는지**

## 6. 개인정보 설계 (바꾸지 말 것)

- 학생에게서 **이름 · 이메일 · 전화번호를 받지 않는다.**
- 학생 로그인은 학급코드·출석번호로 만든 **가상 이메일**:
  `abc123-7@koreatime.local` (실제로 메일이 오가지 않는 내부 식별자)
  - 비밀번호 초기화 시 세대가 붙는다: `abc123-7-2@koreatime.local`
- 화면에 보이는 이름은 학생이 정한 **별명**. 가입 화면에 "실제 이름 말고 별명" 안내가 있다.
- 저장되는 것: 학급 id, 출석번호, 별명, 수준, 진행 상황, 걸린 시간.
- 교사만 이메일로 가입한다(비밀번호 찾기용).
- 학습 기록 문서 id 는 **`{classId}_{번호}`** — uid 가 아니다.
  비밀번호를 초기화해 uid 가 바뀌어도 같은 번호면 기록이 이어지는 이유.

### Firestore 컬렉션
```
teachers/{uid}              { name, email, createdAt }
classes/{classId}           { code(6자), name, teacherId, teacherName, open, resets:{번호:세대}, createdAt }
students/{uid}              { classId, classCode, className, number, nickname, tier, generation, createdAt }
progress/{classId}_{번호}    { classId, number, nickname, tier, chapterIndex, beatIndex, phase,
                              puzzleIndex, solved, wrong, hintsUsed, shards, records,
                              solvedCount, totalPuzzles, percent, elapsedMs, finishedAt, updatedAt }
```

### 규칙 요지 (`firestore.rules`, 테스트 34항목 통과)
- 학생은 **자기 기록만** 읽고 쓴다. 같은 반 친구 기록도 못 읽는다. `list` 는 교사만.
- 학생 가입 시 **로그인 이메일의 학급코드·번호가 문서 내용과 일치**해야 한다 (다른 반 사칭 차단).
- 교사는 **자기가 만든 학급**만 접근. 학급 코드·담당 교사는 수정 불가. `open` 과 `resets` 만 바꾼다.
- 미로그인 사용자는 **코드로 학급 조회만** 가능(가입 전에 필요). 그 밖에는 전부 차단.
- 규칙에 없는 경로는 모두 차단.

## 7. 테스트 돌리는 법

```bash
npm install            # 테스트 도구만 설치한다 (앱 자체는 빌드가 필요 없다)

npm run validate       # 데이터 무결성 — Node 만 있으면 된다
npm run serve          # 다른 터미널에서 로컬 서버를 먼저 띄운다
npm run test:play      # 중·고 두 난이도 전체 플레이 (모든 퍼즐 실제 풀이)
npm run test:ux        # 저장·이어하기, 난이도별 힌트 개방, 휴대폰 화면
npm run test:rules     # Firestore 보안 규칙 34항목 (Java 필요)
npm run deploy         # Hosting + 규칙 배포
```

`package.json` 은 **테스트 도구 전용**이다. 앱은 빌드가 필요 없고,
`firebase.json` 의 `ignore` 에 들어 있어 Hosting 에 올라가지 않는다.
Playwright 브라우저 경로는 `CHROME` 환경변수로 바꿀 수 있다.

`playthrough.mjs` 가 잡아 주는 것: 브리핑 제목·자물쇠 이름·조각이 데이터와 일치하는지,
오답에 오답 안내가 뜨는지, 모든 정답이 실제로 자물쇠를 여는지,
**사료 상자 수와 APA 출처 수가 같은지**(출처 누락 방지), 기록판 6개·성취기준 4개·제작자 표기,
콘솔 오류 0, 380px 가로 넘침 0.

## 8. 작업하다 만난 함정 (같은 실수 반복 금지)

1. **`Element.append(null)` 은 화면에 "null" 글자를 찍는다.**
   조건부로 `null` 을 섞어 넘길 때는 `ui.js` 의 `appendAll()` 을 쓴다.
   (`h()` 도우미는 내부에서 걸러 주지만, `append` 직접 호출은 걸러 주지 않는다)
2. **체험 모드에서 저장을 안 읽던 버그.** `app.js` 부팅에서 로그인하지 않은 경우에도
   `await S.restore()` 를 호출해야 [이어서 하기]가 실제로 이어진다.
3. **장면 SVG 는 `preserveAspectRatio="xMidYMax slice"`** 여야 한다.
   `xMidYMid` 로 두면 넓은 화면에서 건물이 아래로 잘려 나간다.
4. **시네마틱 깊이감** — 먼 능선은 밝게, 가까운 건물은 어둡게. 색이 비슷하면 형태가 안 읽힌다.
5. **첨부 교과서 PDF 의 텍스트 추출** — `pypdf` 로 뽑으면 한글이 깨진다(서브셋 폰트).
   **`pymupdf`** 를 쓰면 정상적으로 추출된다.
6. 데이터를 손으로 고친 뒤 `validate.mjs` 를 건너뛰면, 정답 index 가 어긋난 채 배포된다.

## 9. 앞으로 해볼 만한 것 (우선순위)

1. **Firebase 실제 배포 + 교실 리허설** (5절) — 가장 먼저.
2. 학생 **서술형 소감** 한 칸 추가 → 교사 대시보드에서 모아 보기.
   (같은 저장소의 『아직 오지 않은 광복』에 이미 구현되어 있어 참고 가능)
3. **교사용 학습지 PDF 내보내기** — `@media print` 가 이미 들어가 있어, 결과 화면을
   인쇄하면 학습지가 된다. 전용 인쇄 화면을 만들면 더 좋다.
4. 미션 **오답 유형별 통계** — `save.wrong` 을 이미 문항별로 쌓고 있으니, 대시보드에
   "많이 틀린 문항"을 띄우면 수업 피드백에 바로 쓸 수 있다.
5. 실사 느낌 이미지가 꼭 필요하면 **이미지 슬롯** 방식으로 (같은 저장소의 『아직 오지 않은
   광복』에 GPT Image 생성 스크립트가 있음). 단, 2절의 "실사 오인 방지" 판단을 먼저 재검토할 것.
6. 접근성 — 키보드만으로 전체 플레이 가능한지 점검(현재 `order` 퍼즐은 ▲▼ 버튼이라 가능).
