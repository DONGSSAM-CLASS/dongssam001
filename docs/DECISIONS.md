# 판단 기록 (DECISIONS)

요구사항에 없거나 모호한 부분에 대해 "교실 수업 보조 도구"라는 목적에 가장 부합하는 방향으로 결정한 내용과 이유입니다.

## 0. 시작 전 질문 5개 — 자율 실행 환경이라 답을 기다릴 수 없어 아래 가정으로 진행했습니다. 다른 답을 주시면 반영합니다.

| # | 질문 | 임시 결정(가정) |
| --- | --- | --- |
| 1 | 학생 비밀번호 "4~6자리"는 Firebase Auth 최소 6자 규칙과 충돌합니다. 숫자 PIN 4~6자리를 그대로 쓰되 내부적으로 학급 접두어를 붙여 저장해도 될까요? | **예.** PIN 은 학생 입력 그대로, 실제 Auth 비밀번호는 `{PIN}#{authPrefix}`. 보안 강도는 PIN 과 동일(교실 수준). |

## 1단계 결정

- **관리자 판별**: 커스텀 클레임은 Admin SDK(서버) 없이는 부여할 수 없으므로 `admins/{uid}` 문서 존재 여부로 판별. 최초 관리자는 콘솔에서 수동 생성.
- **학생 식별자는 uid 가 아니라 (classId, number)**: `student_work`·`submissions` 의 문서 ID 를 번호 기준으로 두어 비밀번호 초기화(uid 변경) 후에도 기록이 이어지도록 함. 규칙은 `class_members` 의 uid 로 소유권을 확인.
- **`class_codes` 공개 읽기**: 학생이 로그인 전에 학급을 찾아야 하므로 문서 ID(코드)를 정확히 알 때만 get 허용, list 는 불가. 노출되는 정보는 classId·teacherId·authPrefix 뿐(학생 이름 등은 없음).
- **학생 목록 노출 범위**: 학생은 같은 반 친구 명단을 볼 수 없음(개인정보 최소화). 교사 모니터링에만 사용.
- **세션 삭제/학급 삭제**: 학급은 삭제 금지(보관), 세션·미션은 소유 교사가 삭제 가능. 학생 기록 삭제는 교사만.
- **문서 크기 상한**: 핀 200개·루트 50개(규칙에서 강제) — 문서 1 MiB 한도 대비 충분한 여유.
- **성취기준 ①/② 태그**: 고시 원문은 「역사」 단일 과목이지만 교과서 분책 관행에 따라 단원 1~7 = 역사①, 8~13 = 역사② 로 태그. UI 에서는 "역사(중학교)" 아래 두 그룹으로 표시 예정.
- **Firestore 영속 캐시**: 무료 할당량 절약을 위해 `persistentLocalCache` + 멀티탭 매니저 사용. 크롬북 공용 계정에서는 로그아웃 시 캐시를 비우는 처리를 4단계에서 추가.
- **ESLint 9 고정**: `@eslint/js` 최신(10)은 eslint 10 을 요구해 플러그인들과 충돌 → 9 계열로 고정.
- **에뮬레이터 기본 프로젝트 ID**: `.firebaserc` 기본값을 `demo-history-globe`(데모 접두어 = 실제 프로젝트 없이 에뮬레이터만 동작)로 두고, 실제 배포는 `firebase use --add` 로 alias 를 추가.

## 축소·보류한 기능과 이유

- **서버 측 비밀번호 초기화, 계정 삭제, 대량 학생 계정 일괄 생성**: Cloud Functions(Blaze) 필요 → 위 세대 방식·비활성화·"교사 사전 등록 + 학생 자가 가입"으로 대체.
- **이미지/파일 업로드(Cloud Storage)**: Blaze 필요 → 활동지·결과 이미지는 클라이언트에서 생성해 바로 다운로드(서버 저장 없음).
