# 판단 기록 (DECISIONS)

요구사항에 없거나 모호한 부분에 대해 "교실 수업 보조 도구"라는 목적에 가장 부합하는 방향으로 결정한 내용과 이유입니다.

## 0. 시작 전 질문 5개 — 자율 실행 환경이라 답을 기다릴 수 없어 아래 가정으로 진행했습니다. 다른 답을 주시면 반영합니다.

| # | 질문 | 임시 결정(가정) |
| --- | --- | --- |
| 1 | 학생 비밀번호 "4~6자리"는 Firebase Auth 최소 6자 규칙과 충돌합니다. 숫자 PIN 4~6자리를 그대로 쓰되 내부적으로 학급 접두어를 붙여 저장해도 될까요? | **예.** PIN 은 학생 입력 그대로, 실제 Auth 비밀번호는 `{PIN}#{authPrefix}`. 보안 강도는 PIN 과 동일(교실 수준). |

## 1단계 결정

- **관리자 판별**: 커스텀 클레임은 Admin SDK(서버) 없이는 부여할 수 없으므로 `admins/{uid}` 문서 존재 여부로 판별. 최초 관리자는 콘솔에서 수동 생성.
- **학생 식별자는 uid 가 아니라 (classId, number)**: `student_work`·`submissions` 의 문서 ID 를 번호 기준으로 두어 비밀번호 초기화(uid 변경) 후에도 기록이 이어지도록 함. 규칙은 `class_members` 의 uid 로 소유권을 확인.
- **`class_codes` 공개 읽기**: 학생이 로그인 전에 학급을 찾아야 하므로 문서 ID(코드)를 정확히 알 때만 get 허용, list 는 불가. 노출되는 정보는 classId·teacherId·authPrefix 뿐(학생 이름 등은 없음).
- **학생 목록 노출 범위**: 학생은 같은 반 친구 명단을 볼 수 없음(개인정보 최소화). 교사 모니터링에만 사용.
- **세션 삭제/학급 삭제**: 학급은 삭제 금지(보관), 세션·미션은 소유 교사가 삭제 가능. 학생 기록 삭제는 교사만.
- **문서 크기 상한**: 핀 200개·루트 50개(규칙에서 강제) — 문서 1 MiB 한도 대비 충분한 여유.
- **성취기준 ①/② 태그**: 고시 원문은 「역사」 단일 과목이지만 교과서 분책 관행에 따라 단원 1~7 = 역사①, 8~13 = 역사② 로 태그. UI 에서는 "역사(중학교)" 아래 두 그룹으로 표시 예정.
- **Firestore 영속 캐시**: 무료 할당량 절약을 위해 `persistentLocalCache` + 멀티탭 매니저 사용. 크롬북 공용 계정에서는 로그아웃 시 캐시를 비우는 처리를 4단계에서 추가.
- **ESLint 9 고정**: `@eslint/js` 최신(10)은 eslint 10 을 요구해 플러그인들과 충돌 → 9 계열로 고정.
- **에뮬레이터 기본 프로젝트 ID**: `.firebaserc` 기본값을 `demo-history-globe`(데모 접두어 = 실제 프로젝트 없이 에뮬레이터만 동작)로 두고, 실제 배포는 `firebase use --add` 로 alias 를 추가.

## 4단계 결정

- **가상 이메일은 소문자**: Firebase Auth 가 이메일 주소를 소문자로 정규화하므로(`DEMO24-7@student.local` → `demo24-7@…`) 가상 이메일을 만들 때부터 접두어를 소문자로 쓰고, 규칙에서는 `authPrefix.lower() == emailPrefix()` 로 비교한다. 학급코드 자체는 학생이 읽기 쉽도록 대문자로 표시·저장한다. (이 차이 때문에 학생 가입이 거부되던 문제를 실제 에뮬레이터 검증에서 발견)
- **세션은 학급 생성과 같은 배치에 담지 않는다**: 세션 규칙의 `ownsClass()` 는 `get()` 을 쓰므로 배치 이전 상태를 본다. 학급을 만든 뒤 별도 커밋으로 세션을 만든다(규칙 테스트로 고정).
- **가입·로그인 함수는 프로필 로딩까지 기다린다**: `onAuthStateChanged` 가 `users` 문서 쓰기보다 먼저 도착하면 프로필이 없다고 판단해 로그인 화면으로 되돌아가는 문제가 있어, 가입/로그인 후 `loadProfile()` 을 await 하고 문서 전파 지연에 대비해 최대 3회 재시도한다.
- **핀·루트 저장 구독은 상시 유지**: 화면 전환이나 프로필 갱신으로 구독이 끊긴 사이의 변경이 저장되지 않던 문제 때문에, 저장 구독은 모듈 로드 시 한 번만 걸고 해제하지 않는다. 대신 `openWork` 세대 토큰으로 오래된 읽기 응답이 새 데이터를 덮어쓰지 않게 한다.
- **자유 탐색(로그인 없음) 지원**: `/globe` 는 로그인 없이 지구본을 쓸 수 있고 핀·루트는 `localStorage` 에만 저장한다. 수업 전 교사 준비와 학생 예습에 쓰인다.
- **루트 만들기는 목록에서도 가능**: 3D 마커 클릭만으로는 키보드 사용자가 루트를 만들 수 없어, 핀 목록의 `+` 버튼으로도 순서를 지정할 수 있게 했다.
- **핀 찍기·거리 재기 중에는 마커가 클릭을 가로채지 않음**: 마커 위에 핀을 찍거나 거리를 재려는 클릭이 무시되던 문제를 `pointer-events` 로 해결.
- **핀 200개 / 루트 50개 상한**: 규칙과 UI 모두에서 강제(문서 1 MiB 한도 대비 여유).

## 5단계 결정

- **지구본은 요구 기반 렌더링(`frameloop="demand"`)**: 매 프레임 렌더링하면 소프트웨어 렌더링 환경에서 메인 스레드가 포화되어 같은 페이지의 Firestore 읽기·쓰기가 9초 넘게 지연되는 것을 실측했다. 조작·데이터 변경 시에만 프레임을 요청하도록 바꾸어 쓰기 지연이 0.5초 수준으로 회복되었고 저사양 기기 CPU 사용도 줄었다.
- **따라오기(follow)는 세션 문서의 `follow` 필드로 구현**: 교사가 연대를 바꾸면 700ms 디바운스로 기록하고 학생 화면은 `onSnapshot` 으로 따라온다. 세션 문서 자체를 효과 의존성에 넣으면 "쓰기 → 스냅샷 → 다시 쓰기" 루프가 되므로 카메라 값은 ref 로 들고, 같은 연대는 다시 보내지 않는다(무료 할당량 보호).
- **학급코드 재발급은 새 코드 문서 생성 후 옛 문서 삭제**: `authPrefix` 는 그대로라 이미 가입한 학생의 로그인이 유지된다. 새로 가입하는 학생만 새 코드를 쓴다.
- **비밀번호 초기화 세대는 `class_codes.resets` 맵으로 공개**: 학생이 로그인 전에 자기 가상 이메일 세대를 알아야 하므로 번호→세대만 공개하고 이름은 노출하지 않는다.
- **학급 이동은 교사가 소유한 학급 사이에서만**: 규칙상 다른 교사의 학급에는 명단을 만들 수 없고, 학생의 `users.classId` 도 소유 교사만 바꿀 수 있어 접근 권한이 새지 않는다.
- **중학교 「역사」는 UI 에서 한 묶음**: 고시 원문은 단일 과목이므로 "역사 (중학교)" 아래 ①(세계사 영역)·②(한국사 영역)를 함께 보여주고 단원별로 접었다 편다.
- **자동 추천은 덮어쓰되 교사가 수정 가능**: 성취기준을 고르면 연대 범위·강조 국가·인물이 자동으로 채워지고, 제목은 교사가 직접 고치기 전까지만 제안값을 갱신한다.

## 6단계 결정

- **PDF 는 `window.print()` 가 기본, `html2pdf.js` 는 보조**: 인쇄 경로는 글자가 벡터로 남아 선명하고 용량이 작으며 한글 폰트도 브라우저가 처리한다. html2pdf 는 화면을 이미지로 굽기 때문에 보조 경로로만 둔다(실패 시 인쇄 경로를 안내).
- **활동지 미리보기는 iframe**: 앱의 Tailwind 스타일이 섞여 표 너비 등이 인쇄 결과와 달라지던 문제를 iframe 으로 격리해 해결했다(미리보기 = 내려받은 파일 = 인쇄 결과).
- **HTML 다운로드는 단일 파일 + localStorage 저장**: 서버가 없으므로 학생 입력은 그 브라우저에만 저장한다. 웹폰트를 불러오지 못해도 시스템 한글 글꼴로 열리게 했다.
- **정답은 교사용 미리보기에만**: 거리 계산 문항의 참고 답(대권거리·이동 일수)은 교사 화면에서만 보이고 배부본에는 나가지 않는다.
- **저장된 활동지의 중복 id 정리**: 예전 데이터에 중복 id 가 있어도 불러올 때 인덱스를 붙여 정리한다.

## 7단계 결정

- **Security Rules 는 필터가 아니다**: 학생의 미션 구독 쿼리에 `published == true` 제약을 넣지 않으면, 결과에 읽을 수 없는 문서가 섞일 수 있다는 이유로 쿼리 전체가 거부된다. 규칙 조건과 쿼리 제약을 항상 일치시킨다(교사는 미공개 미션도 보므로 `publishedOnly` 인자로 구분).
- **학생별 색상은 번호에서 결정**: 황금각(137.5°)으로 색상환을 분산시키고 채도·명도를 고정해 색약 상황에서도 구분되도록 했다. 색만으로 구분하지 않도록 목록에 번호·이름·진행 수치를 함께 표시한다.
- **학생 핀·루트는 캔버스 텍스처로 그린다**: 지구본 PNG 내보내기에 학생 기록이 함께 담기도록 하기 위함이며, 한 학생만 볼 때는 DOM 이름표를 덧붙여 읽기 쉽게 했다.
- **PNG 내보내기는 WebGL 캔버스 `toBlob`**: `preserveDrawingBuffer: true` 로 켜 두고 요구 기반 렌더링과 함께 쓴다. 목록형 보기에서는 캔버스가 없어 안내 문구를 띄운다.
- **CSV 는 BOM 포함**: 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM 을 붙이고, 요약(학생별)과 상세(핀·루트별) 두 가지를 제공한다.
- **미션 제출은 학생 1명 = 미션당 문서 1개**: 문서 ID 를 `{missionId}_{번호}` 로 두어 재제출해도 문서가 늘지 않는다.

## 축소·보류한 기능과 이유

- **서버 측 비밀번호 초기화, 계정 삭제, 대량 학생 계정 일괄 생성**: Cloud Functions(Blaze) 필요 → 위 세대 방식·비활성화·"교사 사전 등록 + 학생 자가 가입"으로 대체.
- **이미지/파일 업로드(Cloud Storage)**: Blaze 필요 → 활동지·결과 이미지는 클라이언트에서 생성해 바로 다운로드(서버 저장 없음).
