# 대화/작업 요약 (Claude Code 세션 → Codex 인수인계용)

이 프로젝트가 어떤 요구와 결정으로 만들어졌는지 시간순으로 정리한다. 기술 세부는 `CODEX_HANDOFF.md` 참고.

## 원 요구사항 (사용자 최초 프롬프트 핵심)

- "중·고등학생을 위한 2022 개정 교육과정 연계 교과서 단원별 수능 기출 주제 연동 웹앱" 제작.
- 개발자는 역사 교사와 함께 만드는 입장. **사실 오류가 하나도 있으면 안 됨.**
- 절대 원칙 4가지: ①데이터 날조 금지(근거 없으면 null/verified:false) ②검수 전 비노출 ③저작권(원문 미저장, PDF 링크만) ④비용 0원(Firebase Hosting Spark만, 정적 사이트, localStorage).
- 1차 과목: 한국사. 최근 10개년 수능 본시험. 평가원 공식 PDF로 `#page=N` 딥링크.
- 데이터 수집은 반자동(교사가 PDF 다운로드 → 로컬 파싱 스크립트 → 검수 화면).
- 기술 스택: Vite+React+TS, Tailwind, Noto Sans KR, localStorage, Firebase Hosting(Spark), 정적 JSON, PDF 파싱은 로컬 Python.
- 9단계로 나눠 단계별 진행, 각 단계 후 커밋.

## 진행 경과와 주요 결정

1. **1단계**: 골격 초기화. 이때 저장소 루트에 이미 다른 프로젝트(History Globe)가 있어 파일이 충돌·덮어쓸 뻔한 것을 발견 → **`hansa-suneung/` 하위 폴더로 격리**(dokdo-necut/ 방식). 루트 프로젝트는 그대로 보존.
2. 사용자가 **2022 개정 교육과정(역사) 원문 PDF 2개**와 **교과서 대단원 스크린샷**을 제공 → 성취기준을 원문 그대로 추출해 `curriculum.json`(한국사1·2, 대단원 6/소단원 26)과 `middleSchoolMap.json`(중학교 한국사 영역 연결)을 정확히 작성. 교육과정 영역명이 교과서 대단원명과 일치함을 확인. (원칙 1 준수 — 지어내지 않음.)
3. **2~9단계**를 모두 구현하고 각 단계마다 헤드리스 브라우저(Playwright)로 실제 동작을 검증 후 커밋/푸시:
   - 2 단원 트리·문항 카드·PDF 딥링크 / 3 히트맵 / 4 파싱·검증 스크립트·검수 화면 / 5 검색·역방향 / 6 학습기록·취약단원·D-day / 7 투사·QR·인쇄 / 8 중학생 모드 / 9 Firebase 배포 설정·README.
4. **저작권 설계 변경**: 원 스키마는 `items.json`에 `evidence`(추출 원문)를 넣게 되어 있으나, `public/data`는 정적 배포물이라 원문이 공개된다 → `Item`(배포, evidence 없음)/`ItemDraft`(검수 전용)로 분리하고 검수 화면 다운로드 시 evidence를 제거하도록 함.
5. **종합 QA**: 학생·중학생·교사 3개 페르소나로 전 기능 자동 클릭 테스트(36항목) + 프로덕션 빌드 미리보기(9항목) 통과, 앱 콘솔 에러 0. 폰트 비차단 로드 등 견고성 개선.
6. **배포**: 이 환경엔 Firebase CLI·인증·실제 프로젝트가 없어 실제 배포는 불가 → 사용자가 로컬에서 직접 배포하기로 결정(가장 안전). 배포 절차는 README/CODEX_HANDOFF에 정리됨.

## 아직 안 된 것

- 실제 Firebase Hosting 배포 실행(사용자 로컬, Spark 무료 프로젝트 필요).
- 실제 수능 문항 데이터 입력(`items.json`/`exams.json`은 현재 빈 배열 — 원칙 1에 따라 지어내지 않음). 교사가 PDF → extract.py → 검수 화면 → items.json 커밋.

## 계정 관련 오해 방지

이 앱은 **로그인 계정이 없다**(서버 없음·비용 0원). "교사/학생"은 로그인이 아니라 **화면 구분**(학생/공통 화면 vs `/teacher/*` 화면)과 **중학생 모드 토글**이다.
