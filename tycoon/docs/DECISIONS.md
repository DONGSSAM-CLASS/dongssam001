# 판단 기록 (DECISIONS)

요구사항에 없거나 서로 충돌하는 부분을 어떻게 정했는지, 그 이유와 함께 남깁니다.
이 문서를 읽지 않고 코드를 고치면 무결성이 깨질 수 있습니다.

## 0. 가장 중요한 제약 — Spark(무료) 요금제

교사가 **무료 요금제 유지**를 요구했습니다. 2024년 10월부터 Cloud Functions 는
Blaze(종량제) 없이는 배포 자체가 불가능합니다. 그래서 원래 요구사항 중 아래 항목은
원안대로 구현할 수 없어 대체 설계를 택했습니다.

| 원 요구사항 | 대체 설계 |
| --- | --- |
| 모든 코인 이동을 Callable Function 트랜잭션으로 | **Security Rules 가 복식부기를 강제** (아래 1번) |
| 권한을 Custom Claims 에 저장 | `classes/{c}/members/{uid}.roles` 를 규칙이 `get()` 으로 확인 |
| Callable 이 PIN 검증 후 Custom Token 발급 | 가상 이메일 + PIN = Auth 비밀번호 (아래 2번) |
| 교사가 PIN 초기화 | **세대(generation) 방식** (아래 3번) |
| Cloud Scheduler 가 시세 API 호출 | **GitHub Actions 가 스케줄러 역할** (아래 5번) |
| API 키를 Secret Manager 에 | GitHub Secrets |

### 이 설계로 막을 수 있는 것과 없는 것 (정직하게)

- **막을 수 있는 것**: 권한 없는 사람의 쓰기, 코인 무단 생성·소멸, 한쪽만 늘리는 위조,
  거래 기록 없는 잔액 변경, 과거 거래 재사용, 같은 달 이중 급여, 남의 지갑 조회,
  학생의 자기 역할 승격, 학생의 PIN 목록 열람.
- **막을 수 없는 것**: 대통령(담임교사) 계정 자체가 규칙이 허용하는 범위 안에서
  이상한 값을 넣는 것. 교실 규모에서는 감사 로그(`auditLogs`)로 충분하다고 판단했습니다.

## 1. 원장 — Security Rules 가 복식부기를 강제한다

코인은 절대 생기거나 사라지지 않습니다. 모든 이동은 문서 3개를 하나의 원자적 묶음
(Firestore 트랜잭션 또는 batch)으로 함께 써야 통과합니다.

1. `transactions/{txId}` 생성 (수정·삭제 영구 금지)
2. 보내는 계정 `balance -= amount`, `lastTxId = txId`
3. 받는 계정 `balance += amount`, `lastTxId = txId`

각 계정의 update 규칙이 `getAfter()` 로 **상대 계정도 같은 금액만큼 반대로 움직였는지**
직접 확인합니다. 한쪽만 늘리면 거부됩니다. `tx.createdAt == request.time` 조건이
과거 거래를 재사용하는 공격도 막습니다.

- **MINT 계정**: 발행·소각의 상대 계정입니다. 국고 발행은 `MINT → TREASURY` 이동입니다.
  덕분에 **모든 계정 잔액의 합이 언제나 0** 이고, 통화량 = `-(MINT 잔액)` 입니다.
  MINT 만 음수를 허용합니다. `scripts/verify-ledger.ts` 로 언제든 점검할 수 있습니다.
- **잔액은 `students` 가 아니라 `accounts` 에** 둡니다. 명단 문서와 돈 문서를 분리해야
  "금액 관련 쓰기 전면 금지"를 규칙으로 깔끔하게 표현할 수 있습니다.
- 화면 코드는 `accounts` 문서를 직접 수정하면 안 됩니다. 반드시 `src/lib/ledger.ts`
  의 `moveCoins()` 만 씁니다.

## 2. 학생 로그인 — 가상 이메일 + PIN

- 가상 이메일: `{authPrefix}-{번호}-g{세대}@student.local` (모두 소문자)
- Auth 비밀번호: `{PIN}#{authPrefix}` — Firebase Auth 의 최소 6자 제약을 PIN 4자리를
  유지하면서 넘기기 위한 조합입니다. 보안 강도는 PIN 과 같습니다(교실 수준).
- **첫 로그인이 곧 가입**입니다. 서버가 없어 계정을 미리 만들어 둘 수 없습니다.
  그래서 카드에 "첫 로그인 때 이 PIN을 그대로 입력하세요" 라고 안내합니다.
  잘못 입력하면 그 값이 비밀번호가 되므로, 교사가 PIN 을 초기화해 다시 하게 합니다.
- 번호 가로채기 방지: 첫 로그인 때 `students/{번호}.uid` 가 비어 있을 때만 한 번
  연결할 수 있습니다. 이미 연결된 번호는 다른 계정이 가져갈 수 없습니다.
- 로그인 5회 실패 시 5분 잠금은 브라우저에서 처리합니다(서버 잠금은 불가능).
  Firebase Auth 자체의 남용 방지도 함께 작동합니다.

## 3. PIN 초기화 = 세대 올리기

Admin SDK 가 없어 기존 비밀번호를 바꿀 수 없습니다. 대신 `authGeneration` 을 +1 해서
가상 이메일을 바꾸고, 학생이 새 PIN 으로 다시 가입합니다.
**기록은 uid 가 아니라 번호(`students/{번호}`, `accounts/S{번호}`) 기준**이므로
잔액·거래내역은 그대로 이어집니다. 번호별 세대는 `classCodes/{코드}.generations` 에
공개합니다(학생이 로그인 전에 알아야 하므로). 이름은 공개하지 않습니다.

## 4. 학급 생성은 두 번에 나눠 쓴다

규칙 함수가 `get()` 으로 학급 문서를 확인하는데, 하위 문서를 같은 batch 에 담으면
batch 이전 상태를 보기 때문에 "학급이 없다"고 판단해 거부됩니다. 그래서
① 학급 문서를 먼저 쓰고 ② 나머지를 두 번째 batch 로 씁니다.
(같은 저장소의 History Globe 앱에서도 겪은 문제입니다.)

## 5. 시세 — GitHub Actions 가 스케줄러

브라우저에서 Yahoo Finance 를 직접 부르면 CORS 로 막힙니다. GitHub Actions 가
정해진 시각에 `scripts/fetch-prices.ts` 를 실행하고 서비스 계정으로
`stockPrices/{ticker}` 를 갱신합니다. 브라우저는 캐시만 읽습니다.

- **갱신 주기는 장중 30분 간격** 입니다. 요구사항은 10분이지만 private 저장소의
  Actions 무료 한도(월 2,000분)를 지키기 위해 교사와 합의해 늘렸습니다.
  저장소를 public 으로 바꾸면 10분 간격으로 되돌릴 수 있습니다.
- 시세 제공자는 어댑터(`PriceAdapter`)로 분리했습니다. 기본은 Yahoo,
  실패하면 교사가 종가를 직접 입력하는 화면으로 넘어갑니다(8단계에서 구현).
- 30분 이상 갱신되지 않으면 해당 종목 거래를 자동으로 멈춥니다.

## 6. 그 밖의 결정

- 리전은 `asia-northeast3`(서울), 시간은 모두 Asia/Seoul. 월은 **달력월** 기준입니다.
- 월급은 대통령이 **수동 실행**합니다(자동 지급 스케줄 없음).
- 25명 급여를 한 batch 로 묶지 않습니다. Security Rules 는 batch 1건당 문서 조회를
  20회로 제한하므로 **학생 1명당 1 batch** 로 순차 실행합니다.
  멱등성은 `payrolls/{월}/slips/{번호}` 문서의 create-only 로 보장됩니다.
- 은행 계정(`BANK_DEPOSIT`, `BANK_LOAN`)은 국고의 하위 계정으로 둡니다.
  대출금은 국고에서 나가고 예금 이자도 국고가 지급합니다(통화량 증가 → 인플레이션 수업 소재).
- 학생 번호는 `'07'` 처럼 **두 자리 문자열**로 통일합니다(문서 ID 정렬 때문).
- 학급 코드 알파벳에서 `0/O`, `1/I/L` 처럼 헷갈리는 글자를 뺐습니다.
- 개인정보는 번호·이름(또는 닉네임)만 받습니다. 이메일·전화번호·생년월일은 받지 않습니다.
- 학생이 스스로 PIN 을 바꾸면 교사 화면의 PIN 표시가 실제와 달라집니다.
  이 경우 초기화로 해결하도록 화면에 안내 문구를 넣었습니다.
