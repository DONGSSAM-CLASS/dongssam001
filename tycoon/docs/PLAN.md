# 단계별 구현 계획

각 단계가 끝나면 **실행 방법과 확인 항목을 보고하고 멈춥니다.**
지정하지 않은 기능이나 디자인은 임의로 바꾸지 않습니다. 애매하면 추측하지 말고 묻습니다.

모든 단계에 공통으로 적용되는 규칙:

- 코인이 움직이는 모든 코드는 `src/lib/ledger.ts` 의 `moveCoins()` 만 씁니다.
  `accounts` 문서를 직접 수정하면 Security Rules 가 거부합니다.
- 새 컬렉션을 쓰려면 `firestore.rules` 에 규칙을 먼저 추가하고,
  `tests/rules/` 에 "되는 경우 / 안 되는 경우" 테스트를 함께 씁니다.
- UI 텍스트·안내·에러 메시지는 전부 한국어입니다. 대상은 중학생과 교사입니다.
- 금액은 천 단위 콤마 + "코인", 증가는 파랑·감소는 빨강(주식 화면만 반대).
- 위험한 작업은 `DangerConfirm` 으로 학급 코드를 다시 입력받습니다.

---

## 1단계 — 세팅·인증·학급·명단 ✅ 완료

- Vite + React 19 + TS + Tailwind 4, Firebase 연결, 에뮬레이터
- 교사 Google 로그인 / 학생 학급코드+번호+PIN 로그인 (5회 실패 5분 잠금)
- 학급 생성 + 6자리 코드, 학생 일괄 등록(붙여넣기·CSV), PIN 발급, 인쇄용 로그인 카드
- PIN 초기화(세대 방식), 학생 PIN 변경
- **원장 엔진**: MINT/TREASURY/학생 지갑, 복식부기 규칙, 국고 발행·소각 화면
- Rules 테스트 20개 + 단위 테스트 8개 통과

## 2단계 — 조직(부처) 편집·역할 배정·조직도

- 부처 추가·삭제·이름 변경·순서 변경, 직책명 변경, 업무 설명, 정원, 직책별 월급
- 부처에 학생 배정 (한 학생이 여러 roleKey 를 가질 수 있음 — 배열)
- "2026년 실제 정부조직 명칭으로 일괄 변경" 버튼 (`officialName2026` 사용, roleKey 유지)
- 조직도 트리 화면 (대통령 → 국무총리/국회의장 → 각 부처)
- 규칙: `ministries` 는 이미 열려 있음. `members.roles` 는 교사만 쓰기 가능(완료)
- 확인 항목: 이름을 바꿔도 기획재정부 장관의 권한이 그대로인지

## 3단계 — 월급·세금·급여명세서

- 직책별 월급 설정(개인별 조정 포함)
- **월급 일괄 지급**: 대상 월(YYYY-MM) 선택 → 학생 1명당 1 batch 로 순차 실행
  - 각 학생마다 `PAYROLL`(국고→학생)과 `TAX`(학생→국고) 두 거래
  - `payrolls/{월}/slips/{번호}` 를 같은 묶음에 `create` → 두 번째 실행은 규칙이 거부(멱등)
  - 중간에 끊겨도 이어서 실행되게 진행 상태를 `payrolls/{월}.paidCount` 에 기록
- 소득세: 단일세율 10% 기본, 누진세 표 설정 (`src/lib/money.ts` 의 `calcIncomeTax` 완료)
- 급여명세서: 총액·세금·실수령액·보류 여부와 사유
- **월급 일괄 회수**: `CLAWBACK` 역거래, 사유 필수, `DangerConfirm` 필수
- 확인 항목: 같은 달 두 번 실행해도 한 번만 지급되는지

## 4단계 — 지적 제도·상벌점

- 지적 부여(날짜·사유·대상 월), `warningCounts` 집계 갱신
- 한 달 지적이 기준치(기본 3회) 이상 → 다음 달 `salaryHolds` 자동 생성 → 일괄 지급에서 제외
- 보류 해제는 **대통령만**. 지급 전 해제 → 일괄 포함 / 지급 후 해제 → "개별 지급" 버튼
- 지적 취소(사유·이력 남김, 삭제 불가)
- 학생 화면: 이번 달 n/3회, 기준치의 2/3 도달 시 경고 배지
- 상점·벌점: 여러 학생 일괄 선택, 프리셋(`meritPresets`) 추가·수정·삭제
  - 벌점 코인은 국고로(`PENALTY`), 상점은 국고에서(`MERIT`)
  - 잔액 부족 시 부족분을 `students.debts` 에 기록
- 확인 항목: 9월 지적 3회 학생이 10월 일괄 지급에서 빠지는지, 비대통령이 해제하면 거부되는지

## 5단계 — 부동산 청약

- 회차(`auctions/{roundId}`) 단위 관리, 월 1회
- **오프라인 결과 입력(필수)**: 학생·자리·낙찰가 입력 → "대금 일괄 차감"(`AUCTION` → 국고)
  - 잔액 부족 학생은 경고 + 처리 방법 선택(대출 연계 / 미납 기록)
- **온라인 경매(선택)**: 좌석 배치도 편집(행×열, 사용 불가 칸), 밀봉/공개 입찰, 최저가,
  1인 1자리, 입찰 시 `ESCROW` 계정으로 가상 잠금, 마감 후 낙찰 확정
- 회차별 결과 차트(평균가·최고가 추이)
- 규칙 추가 필요: `auctions`, `bids`, `seats` + `AUCTION`/`ESCROW` 거래 유형
  - 권한: 대통령과 `FINANCE_MINISTER` 만 차감 가능 (일반 장관은 불가)

## 6단계 — 은행·예금·대출·신용점수

- `FINANCE_MINISTER` 는 전체 보유고 조회 가능(규칙 완료), 다른 학생은 본인 것만
- 은행 영업 시작/중지, 자유입출금(무이자), 정기예금(2주·4주, 만기 이자는 국고에서)
- 대출: 금리·한도·기간·상환 방식 설정, 대통령이 정한 **금리 상한** 안에서만
  - 신청(금액·용도 필수) → 기재부 장관 심사 → 승인 시 입금
  - 기준 금액 이상은 국무총리/국회의장 결재 추가(7단계 연동)
  - **본인 대출 자기 승인 금지** — 대통령이 심사
  - 연체 시 신용점수(기본 1000) 차감, 한도에 반영
- 은행 현황판: 총예금·총대출·연체율·국고 잔액
- 정기예금 만기 정산은 GitHub Actions 야간 배치로 하루 1회

## 7단계 — 전자결재·관보

- 장관이 문서 상신(유형·제목·내용·예산·첨부)
- 결재권자: 국무총리·국회의장. 라인 3모드(①둘 중 1인 ②둘 다 ③유형별 지정), 기본 ①
- **본인이 상신한 문서는 본인이 결재할 수 없다** (규칙으로 강제)
- 예산 포함 문서 최종 승인 → "집행 대기" → 대통령/기재부 장관이 집행해야 코인 이동
- 대통령 비토, 결재함 3탭(상신·대기·완료), 알림 배지
- 승인된 정책은 `notices`(관보)에 자동 게시

## 8단계 — 주식

- 종목 관리(대통령), 기본 추천 10종목
- 시세: GitHub Actions(`scripts/fetch-prices.ts`, 완료) → `stockPrices` 캐시
  - 어댑터 교체 가능(Yahoo 기본 / KIS 대안 / 교사 수동 입력 백업)
  - 30분 이상 미갱신 → 해당 종목 거래 중지
- 코인 환산: `반올림(원화 ÷ 환산비율)`, 기본 1코인 = 1,000원, 종목별 조정 가능
  - 화면에 "실제 가격 ₩xx,xxx / 교실 가격 xx코인" 병기
- 시장가 매수·매도만, 정수 주 단위, 수수료·거래세는 국고로
- **신용거래·공매도·레버리지 금지**, 보유 코인 범위 안에서만
- **투자 일지 필수** — 한 줄 이상 없으면 주문 거부(규칙으로도 강제)
- 포트폴리오(평균 매입가·평가액·수익률·실현 손익), 1개월 차트
- 수익률 순위표는 기본 비공개, 1인당 투자 한도(순자산 대비 %)

## 9단계 — 대시보드·리포트·용어 사전·백업

- 교실 TV용 대시보드 모드(큰 글씨·전체화면)
- 월말 경제 보고서(세수·지출·통화량 변화·청약 평균가·대출/예금 추이·투자 참여율), 인쇄 가능
- 학생 개인 월말 리포트(소득·지출·저축률·투자 수익률·한 줄 회고)
- 경제 용어 사전 + 각 화면 "?" 툴팁
- CSV·JSON 내보내기, 학기 초기화(`DangerConfirm` 필수)

## 10단계 — 배포·교사용 안내서

- `docs/TEACHER_SETUP.md` 를 학기 운영 안내까지 확장
- Hosting 배포 확인, 접근성 점검(16px·대비·터치 44px)
